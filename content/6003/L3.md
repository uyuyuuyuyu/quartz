# 1. Review of Mathematical Foundations

The lecture begins by reviewing mathematical concepts from previous lectures.

These concepts are important for understanding cryptographic primitives.

## 1.1 Functions

A function is a deterministic mapping:

$$
f:X\rightarrow Y
$$

where:

- $X$ is the domain.
- $Y$ is the codomain.
- Every input $x\in X$ maps to exactly one output $f(x)\in Y$.

### Injective Function

A function is injective if different inputs always produce different outputs.

$$
f(x_1)=f(x_2)\implies x_1=x_2
$$

There are no collisions between different inputs.

### Surjective Function

A function is surjective if every element of the codomain has at least one input mapped to it.

$$
\forall y\in Y,\ \exists x\in X:f(x)=y
$$

### Bijective Function

A function is bijective if it is both injective and surjective.

Every output corresponds to exactly one input.

Therefore, a bijective function is invertible.

For finite sets, a bijection requires:

$$
|X|=|Y|
$$

### Permutation

A permutation is a bijective function from a set to itself.

$$
f:X\rightarrow X
$$

A permutation rearranges the elements of the set without creating collisions.

This concept becomes particularly important when discussing block ciphers.

---

## 1.2 Groups

A group consists of a set $G$ and an operation $*$ satisfying four properties.

### 1. Closure

For all $a,b\in G$:

$$
a*b\in G
$$

The operation always produces another element in the set.

### 2. Associativity

$$
(a*b)*c=a*(b*c)
$$

### 3. Identity

There exists an identity element $e$ such that:

$$
a*e=e*a=a
$$

### 4. Inverse

Every element $a$ has an inverse $a^{-1}$ satisfying:

$$
a*a^{-1}=a^{-1}*a=e
$$

### Example: Modular Addition

Consider:

$$
\mathbb Z_6=\{0,1,2,3,4,5\}
$$

under addition modulo 6.

The identity is 0.

Every element has an additive inverse.

For example:

$$
2+4\equiv0\pmod6
$$

Therefore:

$$
(\mathbb Z_6,+)
$$

is a group.

---

## 1.3 Rings

A ring has two operations, usually addition and multiplication.

Addition forms a commutative group.

Multiplication is closed and associative.

Multiplication is also distributive over addition:

$$
a(b+c)=ab+ac
$$

Unlike a field, a ring does not require every nonzero element to have a multiplicative inverse.

### Example: Integers Modulo 6

$$
(\mathbb Z_6,+,\times)
$$

is a ring.

However, 2 does not have a multiplicative inverse modulo 6.

There is no $x\in\mathbb Z_6$ satisfying:

$$
2x\equiv1\pmod6
$$

Therefore, $\mathbb Z_6$ is not a field.

---

## 1.4 Fields

A field is a ring in which multiplication over the nonzero elements also forms a commutative group.

Every nonzero element must have a multiplicative inverse.

### Example: Integers Modulo 7

$$
\mathbb Z_7=\{0,1,2,3,4,5,6\}
$$

Since 7 is prime, every nonzero element has a multiplicative inverse.

For example:

$$
2\cdot4\equiv1\pmod7
$$

Therefore, 4 is the multiplicative inverse of 2.

The set $\mathbb Z_7$ with modular addition and multiplication is a field.

### Multiplicative Groups

The notation:

$$
\mathbb Z_N^*
$$

represents the elements of $\mathbb Z_N$ that have multiplicative inverses modulo $N$.

Equivalently:

$$
\mathbb Z_N^*
=
\{x\in\mathbb Z_N:\gcd(x,N)=1\}
$$

For example:

$$
\mathbb Z_6^*=\{1,5\}
$$

because only 1 and 5 are coprime to 6.

Under multiplication modulo 6, these elements form a group.

---

## 1.5 XOR and Finite Fields

XOR is an important operation in cryptography.

Its key properties include:

$$
a\oplus0=a
$$

$$
a\oplus a=0
$$

$$
a\oplus b=b\oplus a
$$

For bit strings, XOR is performed independently on each bit.

A bit string is its own additive inverse:

$$
x\oplus x=0
$$

Therefore, fixed-length bit strings form a commutative group under XOR.

With a suitable multiplication operation, bit strings can also form a finite field.

For example:

$$
GF(2^8)
$$

is a finite field with 256 elements.

The lecturer explains that this mathematical structure is important for AES.

**Important:** XOR alone defines the additive group. A suitable multiplication operation is also needed to obtain a field.

# 2. Perfect Security vs. Computational Security

## 2.1 Perfect Security

The one-time pad is an example of a perfectly secure encryption scheme.

Encryption:

$$
C=M\oplus K
$$

Decryption:

$$
M=C\oplus K
$$

Perfect secrecy requires:

- A uniformly random key.
- A key at least as long as the message.
- A fresh key for each message.
- No key reuse.

The main disadvantage is that a new secret key as long as the message must be securely shared.

For large amounts of communication, this is impractical.

---

## 2.2 Computational Security

Computational security replaces the requirement of perfect secrecy with the requirement that no efficient adversary can successfully attack the system.

An algorithm may be theoretically breakable while still being computationally secure.

For example, an adversary could attempt to guess every possible key.

However, this may require an infeasible amount of computation.

### Security Levels

| Security level | Approximate attack complexity |
|---|---|
| 80-bit | $2^{80}$ operations |
| 128-bit | $2^{128}$ operations |
| 256-bit | $2^{256}$ operations |

The lecture presents 128-bit security as sufficient for many practical applications.

The general goal is:

> No computationally efficient adversary should have a meaningful advantage in breaking the cryptographic system.

### Efficient Algorithms

In theoretical cryptography, an efficient algorithm is usually modeled as one whose running time is polynomial in the security parameter $k$.

Examples of polynomial running times include:

$$
k,\quad k^2,\quad k^3
$$

An exhaustive search over all $k$-bit keys requires:

$$
2^k
$$

operations.

This is exponential in $k$.

### Negligible Advantage

A probability is negligible if it eventually becomes smaller than the inverse of every positive polynomial in the security parameter.

Informally, a negligible advantage is too small to be useful to an efficient adversary.

# 3. Pseudorandom Generators (PRGs)

## 3.1 Definition

A pseudorandom generator is an efficiently computable deterministic function that expands a short seed into a longer pseudorandom output.

$$
F:\{0,1\}^{k}\rightarrow\{0,1\}^{k+\ell}
$$

where:

- $k$ is the seed length.
- $\ell$ is the number of additional output bits.
- $k+\ell$ is the total output length.

For example, a PRG may expand a 128-bit seed into a much longer bit stream.

The output is called a **keystream** when used for stream encryption.

---

## 3.2 How a PRG Works

A PRG usually has:

1. A secret key $K$.
2. An internal state $S$.
3. An optional initial value (IV).
4. An update function.
5. A generation function.

The initial state is established using the secret key and possibly the IV.

The update function changes the internal state.

The generation function produces the next part of the keystream.

Conceptually:

```text
Secret key K + IV
       |
       v
  Initialize state
       |
       v
   Update state
       |
       v
 Generate keystream
       |
       v
  L1, L2, L3, ...
```

Practical generators may produce one bit, several bits, or entire blocks per update.

---

## 3.3 PRGs Are Deterministic

A PRG is deterministic.

The same seed and initial state always produce the same keystream.

$$
F(K)=F(K)
$$

More explicitly, for a generator using an IV:

$$
F(K,IV)=L
$$

Calling the generator again with the same $K$ and $IV$ produces the same $L$.

This is necessary because the sender and receiver need to reproduce the same keystream.

---

## 3.4 Pseudorandom vs. Truly Random

A PRG does not generate truly random bits.

Suppose a PRG has a $k$-bit seed.

There are only:

$$
2^k
$$

possible seeds.

Therefore, for a fixed output length, there can be at most $2^k$ different PRG outputs.

If the PRG generates $m$ bits, truly random output has:

$$
2^m
$$

possible values.

When $m>k$:

$$
2^m>2^k
$$

Consequently, a PRG cannot cover all possible output strings.

An adversary with unlimited computational resources could enumerate all possible seeds and their outputs.

However, for sufficiently large keys, this may be computationally infeasible.

The security objective is therefore:

$$
F(K)\approx U_m
$$

where $U_m$ denotes a uniformly random $m$-bit string.

The approximation means computational indistinguishability, not mathematical equality.

# 4. Stream Ciphers

## 4.1 Constructing a Stream Cipher

A PRG generates a keystream.

A stream cipher uses this keystream to encrypt a message.

Let:

- $M$ be the plaintext.
- $L$ be the keystream.
- $C$ be the ciphertext.

Encryption:

$$
\boxed{C=M\oplus L}
$$

Decryption:

$$
\boxed{M=C\oplus L}
$$

Decryption works because:

$$
C\oplus L
=
(M\oplus L)\oplus L
$$

and:

$$
L\oplus L=0
$$

Therefore:

$$
C\oplus L=M
$$

The PRG itself does not encrypt anything.

It only produces the keystream.

Encryption occurs when the plaintext is combined with the keystream.

---

## 4.2 Keystream Reuse

The same keystream must not be reused to encrypt two different messages.

Suppose:

$$
C_1=M_1\oplus L
$$

and:

$$
C_2=M_2\oplus L
$$

An adversary can calculate:

$$
C_1\oplus C_2
$$

Substituting:

$$
C_1\oplus C_2
=
(M_1\oplus L)\oplus(M_2\oplus L)
$$

Rearranging:

$$
=M_1\oplus M_2\oplus L\oplus L
$$

Since:

$$
L\oplus L=0
$$

we obtain:

$$
\boxed{C_1\oplus C_2=M_1\oplus M_2}
$$

This reveals a relationship between the plaintexts.

Therefore, practical stream ciphers must avoid keystream reuse.

The slides emphasize changing the IV for every new message when the cipher uses an IV, and changing the key after a specified amount of generated keystream.

---

# 5. PRG Security

The lecturer introduces a formal security game to define what it means for a PRG to be secure.

The main question is:

> Can an efficient adversary distinguish a real PRG output from a truly random bit string?

## 5.1 The PRG Security Game

The game involves two participants:

- Challenger
- Adversary $A$

### Step 1: Challenger chooses a bit

The challenger randomly chooses:

$$
b\in\{0,1\}
$$

The value of $b$ determines which world the adversary encounters.

### Step 2: Challenger selects the world

If:

$$
b=1
$$

the challenger uses the real world.

It chooses a random secret key $K$ and returns the PRG output:

$$
L=F(K)
$$

If:

$$
b=0
$$

the challenger uses the ideal world.

It returns a truly random bit string:

$$
L\leftarrow U_m
$$

### Step 3: Adversary guesses

The adversary observes $L$ and outputs:

$$
b'\in\{0,1\}
$$

where:

- $b'=1$ means the adversary guesses real.
- $b'=0$ means the adversary guesses ideal.

The adversary wins if:

$$
b'=b
$$

---

## 5.2 Understanding the Probability Notation

Consider:

$$
\Pr[A^{b=1}=1]
$$

This means:

> The probability that the adversary outputs 1 when interacting with the real world.

Similarly:

$$
\Pr[A^{b=0}=1]
$$

means:

> The probability that the adversary outputs 1 when interacting with the ideal world.

The superscript tells us which world the adversary is interacting with.

The final equality tells us what the adversary outputs.

---

## 5.3 PRG Security Advantage

The distinguishing advantage is:

$$
\boxed{
\operatorname{Adv}^{PRG}_{F}(A)
=
\left|
\Pr[A^{b=1}=1]
-
\Pr[A^{b=0}=1]
\right|
}
$$

The first term represents the probability of guessing real in the real world.

The second represents the probability of incorrectly guessing real in the ideal world.

The absolute value measures how differently the adversary behaves in the two worlds.

### Interpretation

| Advantage | Meaning |
|---|---|
| $0$ | No distinguishing ability |
| Close to $0$ | Very little distinguishing ability |
| $1$ | Perfect distinguishing ability |

A secure PRG should have negligible advantage against every efficient adversary.

An adversary that guesses randomly has advantage 0.

Even though it wins the game with probability $1/2$, its guesses do not distinguish between the two worlds.

# 6. Toy PRG Example

The lecture spends considerable time analyzing a small PRG.

This example appears in Chapter 4, slide 16.

The generator expands a 3-bit key into a 4-bit output.

$$
F:\{0,1\}^3\rightarrow\{0,1\}^4
$$

Let:

$$
K=(K_1,K_2,K_3)
$$

The output is:

$$
L=(L_1,L_2,L_3,L_4)
$$

The generator is defined by:

$$
L_1=K_1\oplus K_2
$$

$$
L_2=K_2\oplus K_3
$$

$$
L_3=K_3\oplus K_1
$$

$$
L_4=L_1\oplus(K_2\land K_3)
$$

Here:

- $\oplus$ denotes XOR.
- $\land$ denotes logical AND.

---

## 6.1 Computing All Possible Outputs

There are three key bits.

Therefore, the number of possible keys is:

$$
2^3=8
$$

We can calculate the output for every key.

| Key | $L_1$ | $L_2$ | $L_3$ | $L_4$ | Output |
|---|---|---|---|---|---|
| 000 | 0 | 0 | 0 | 0 | 0000 |
| 001 | 0 | 1 | 1 | 0 | 0110 |
| 010 | 1 | 1 | 0 | 1 | 1101 |
| 011 | 1 | 0 | 1 | 0 | 1010 |
| 100 | 1 | 0 | 1 | 1 | 1011 |
| 101 | 1 | 1 | 0 | 1 | 1101 |
| 110 | 0 | 1 | 1 | 0 | 0110 |
| 111 | 0 | 0 | 0 | 1 | 0001 |

Some keys produce identical outputs.

The six distinct outputs are:

$$
\{
0000,
0110,
1101,
1010,
1011,
0001
\}
$$

The lecturer initially counted five distinct outputs, but corrected the result to six after the break.

---

## 6.2 Attack 1: Enumerating All Outputs

The adversary computes every possible PRG output and stores the results in a table.

It then uses the following strategy:

- If the observed output is in the table, guess real.
- Otherwise, guess ideal.

### Real World

Every real PRG output must appear in the table.

Therefore:

$$
\Pr[A^{b=1}=1]=1
$$

### Ideal World

A truly random four-bit string has:

$$
2^4=16
$$

possible values.

Only six of these values appear in the PRG's output table.

Therefore:

$$
\Pr[A^{b=0}=1]=\frac{6}{16}
$$

### Advantage

$$
\operatorname{Adv}^{PRG}_{F}(A)
=
\left|
1-\frac{6}{16}
\right|
$$

$$
=
\frac{10}{16}
$$

$$
\boxed{
\operatorname{Adv}^{PRG}_{F}(A)=\frac58=0.625
}
$$

The adversary has a substantial distinguishing advantage.

Therefore, this toy PRG is insecure.

### Why Is the Probability $6/16$?

The numerator 6 is the number of distinct outputs the PRG can produce.

The denominator 16 is the number of all possible four-bit strings.

The probability that a uniformly random four-bit string appears in the PRG's output table is therefore:

$$
\frac{6}{16}
$$

---

## 6.3 Attack 2: Finding an XOR Pattern

The lecturer demonstrates another attack that does not require storing all possible outputs.

Recall:

$$
L_1=K_1\oplus K_2
$$

$$
L_2=K_2\oplus K_3
$$

$$
L_3=K_3\oplus K_1
$$

Consider:

$$
L_1\oplus L_2\oplus L_3
$$

Substituting:

$$
=
(K_1\oplus K_2)
\oplus
(K_2\oplus K_3)
\oplus
(K_3\oplus K_1)
$$

Rearranging:

$$
=
K_1\oplus K_1
\oplus
K_2\oplus K_2
\oplus
K_3\oplus K_3
$$

Every key bit cancels.

Therefore:

$$
\boxed{
L_1\oplus L_2\oplus L_3=0
}
$$

This holds for every possible key.

### Adversary Strategy

The adversary receives an output $L$.

It calculates:

$$
L_1\oplus L_2\oplus L_3
$$

If the result is zero, it guesses real.

Otherwise, it guesses ideal.

### Real World

For a real PRG output, the relationship always holds.

$$
\Pr[A^{b=1}=1]=1
$$

### Ideal World

For three independent random bits, their XOR equals zero with probability:

$$
\frac12
$$

Therefore:

$$
\Pr[A^{b=0}=1]=\frac12
$$

### Advantage

$$
\operatorname{Adv}^{PRG}_{F}(A)
=
\left|
1-\frac12
\right|
$$

$$
\boxed{
\operatorname{Adv}^{PRG}_{F}(A)=\frac12
}
$$

This also demonstrates that the toy PRG is insecure.

### Main Lesson

A PRG is insecure if an efficient adversary can identify a pattern that occurs with a noticeably different probability than it would in truly random data.

The attack does not necessarily need to recover the key.

It only needs to distinguish the output from random.

# 7. Next-Bit Security

The lecturer briefly introduces next-bit security.

The idea is that if a secure PRG can expand a $k$-bit seed into $k+1$ bits, then this construction can be used to build a PRG that generates a polynomially longer output.

For example:

$$
F_1:\{0,1\}^k\rightarrow\{0,1\}^{k+1}
$$

can be used as a building block for:

$$
F_\ell:\{0,1\}^k\rightarrow\{0,1\}^{k+\ell}
$$

where $\ell$ is polynomially bounded by $k$.

The lecturer does not prove this result.

The purpose is to show that securely generating even one additional pseudorandom bit is theoretically significant.

# 8. Stream Cipher Case Studies

The lecturer presents two stream cipher examples:

- RC4
- ChaCha

These examples are introduced as an excursion.

The lecturer explicitly says that the excursion's implementation details are not included in quizzes.

---

## 8.1 RC4

RC4 is an old stream cipher that was widely used in protocols such as WEP.

It generates a keystream using an internal state array.

The state is initialized and repeatedly updated through swapping operations.

### Security Problems

The lecturer explains that RC4's state mixing is insufficient.

As a result, some output values occur with biased probabilities.

These statistical biases allow adversaries to distinguish RC4 output from truly random bits.

RC4 was also used in WEP with a 24-bit initialization vector.

A short IV creates a substantial risk of repetition.

If the same key and IV are reused, the same keystream can be generated.

This can expose relationships between encrypted messages and enable practical attacks.

### Main Lesson

A cryptographic algorithm can have a seemingly reasonable key length but still be insecure because of weaknesses in its construction or usage.

RC4 is presented as an example of a broken stream cipher.

---

## 8.2 ChaCha

ChaCha is presented as an example of a modern stream cipher.

Its core is based on three operations:

1. Modular addition
2. Bitwise rotation
3. XOR

These are often called ARX operations.

ChaCha operates on a 512-bit state.

The ChaCha20 mode described in the slides uses a 256-bit secret key, a nonce, and a counter.

The core permutation transforms the internal state.

The input is then added back to the permutation output in a feed-forward step.

This produces a keystream block.

A counter is incremented to generate successive blocks.

Conceptually:

```text
Key + Nonce + Counter
         |
         v
   ChaCha Permutation
         |
         v
 Add Original Input
         |
         v
    Keystream Block
```

The lecturer uses ChaCha to illustrate how a permutation can be used as part of a secure stream cipher.

---

# 9. Introduction to Block Ciphers

The lecture then moves from stream ciphers to block ciphers.

A stream cipher generates a keystream and combines it with plaintext.

A block cipher directly transforms a fixed-size plaintext block into a ciphertext block of the same size.

## 9.1 Definition

A block cipher is a family of keyed permutations.

$$
E:\mathcal K\times\mathcal M\rightarrow\mathcal M
$$

For every fixed key $K$:

$$
E_K:\mathcal M\rightarrow\mathcal M
$$

must be a permutation.

Here:

- $\mathcal K$ is the key space.
- $\mathcal M$ is the plaintext space.
- The ciphertext space is identical to the plaintext space.

For example, AES uses 128-bit blocks.

---

## 9.2 Why Must a Block Cipher Be a Permutation?

A block cipher must support both encryption and decryption.

Suppose two different plaintexts produce the same ciphertext:

$$
E_K(M_1)=E_K(M_2)
$$

where:

$$
M_1\neq M_2
$$

The receiver would not know whether the original plaintext was $M_1$ or $M_2$.

Therefore, encryption must be injective.

Since the plaintext and ciphertext spaces have the same finite size, the mapping must be bijective.

Thus, every fixed-key block cipher must be a permutation.

Different keys may define different permutations.

Outputs under different keys may coincide, but each individual keyed mapping must remain a permutation.

---

# 10. Random Bits vs. Uniformly Random Permutations

This is an important distinction between PRG security and block cipher security.

## 10.1 Random Bits

Suppose we independently generate two-bit strings.

Possible outputs are:

$$
\{00,01,10,11\}
$$

Each string has probability:

$$
\frac14
$$

Different random draws may produce the same value.

For example:

```text
First draw:   10
Second draw:  01
Third draw:   10
```

The first and third draws collide.

This is allowed for independently random outputs.

---

## 10.2 Uniformly Random Permutation

Now consider a permutation over:

$$
\{00,01,10,11\}
$$

A permutation must assign every input a unique output.

For example:

| Input | Output |
|---|---|
| 00 | 10 |
| 01 | 11 |
| 10 | 00 |
| 11 | 01 |

There are no collisions between distinct inputs.

There are:

$$
4!=24
$$

possible permutations over this set.

A uniformly random permutation means that one of these 24 permutations is chosen with equal probability.

Each permutation has probability:

$$
\frac1{24}
$$

Once the permutation is selected, it remains fixed during the security experiment.

### General Formula

For an $n$-bit block, the number of possible inputs is:

$$
2^n
$$

The number of possible permutations is:

$$
\boxed{(2^n)!}
$$

For example, a three-bit block has eight possible inputs.

Therefore, there are:

$$
8!=40320
$$

possible permutations.

---

## 10.3 Why Is the Distinction Important?

A block cipher must be invertible.

Independent random outputs could collide, making unique decryption impossible.

Therefore, comparing a block cipher against independently random output would be inappropriate.

Instead, the ideal world for block cipher security uses a uniformly random permutation.

| Property | Random bits | Random permutation |
|---|---|---|
| Outputs | Sampled independently | Determined by a randomly chosen bijection |
| Collisions | Allowed | Not for distinct inputs |
| Invertible mapping | Not necessarily | Always |
| Security notion | PRG | PRP |

---

# 11. PRP Security

PRP stands for **Pseudorandom Permutation**.

A secure block cipher should behave like a uniformly random permutation.

## 11.1 PRP Security Game

The challenger randomly chooses:

$$
b\in\{0,1\}
$$

### Real World: $b=1$

The challenger chooses a secret key:

$$
K\leftarrow\mathcal K
$$

The adversary submits plaintexts $M_i$.

The challenger returns:

$$
C_i=E_K(M_i)
$$

### Ideal World: $b=0$

The challenger chooses a uniformly random permutation:

$$
\pi\leftarrow\operatorname{Perm}(n)
$$

The adversary submits plaintexts $M_i$.

The challenger returns:

$$
C_i=\pi(M_i)
$$

### Adversary's Goal

The adversary observes the ciphertexts and guesses whether they came from the real block cipher or the random permutation.

It outputs:

$$
b'\in\{0,1\}
$$

The adversary wins if:

$$
b'=b
$$

---

## 11.2 PRP Advantage

The PRP advantage is:

$$
\boxed{
\operatorname{Adv}^{PRP}_{E}(A)
=
\left|
\Pr[A^{E_K}=1]
-
\Pr[A^\pi=1]
\right|
}
$$

The first probability measures how often the adversary outputs real when interacting with the real block cipher.

The second measures how often it outputs real when interacting with a random permutation.

A secure block cipher should have negligible PRP advantage against every efficient adversary.

---

# 12. Strong PRP Security

Strong PRP security extends ordinary PRP security.

In the ordinary PRP game, the adversary can request encryptions.

In the strong PRP game, the adversary can request both encryptions and decryptions.

### Real World

The adversary has access to:

$$
E_K
$$

and:

$$
E_K^{-1}
$$

### Ideal World

The adversary has access to:

$$
\pi
$$

and:

$$
\pi^{-1}
$$

The adversary must determine whether it is interacting with the real cipher or the random permutation.

### Comparison

| Security notion | Adversary's access |
|---|---|
| PRG | Generated pseudorandom output |
| PRP | Encryption oracle |
| Strong PRP | Encryption and decryption oracles |

Strong PRP considers a stronger adversary because it provides access to additional operations.

---

# 13. Toy Block Cipher Example

The lecturer introduces a simple three-bit block cipher.

Let:

$$
M=(M_1,M_2,M_3)
$$

and:

$$
K=(K_1,K_2,K_3)
$$

Encryption is defined as:

$$
C_1=M_2\oplus K_2
$$

$$
C_2=M_1\oplus K_1
$$

$$
C_3=M_3\oplus K_3
$$

The cipher swaps the first and second plaintext bits and XORs them with the corresponding key bits.

The mapping is invertible for every fixed key.

Therefore, it satisfies the basic definition of a block cipher.

However, it is not PRP-secure.

---

## 13.1 Chosen-Plaintext Attack

The adversary chooses two plaintexts:

$$
M^{(1)}=000
$$

$$
M^{(2)}=001
$$

Only the third plaintext bit changes.

The encryption equations imply:

$$
C_1^{(1)}=C_1^{(2)}
$$

and:

$$
C_2^{(1)}=C_2^{(2)}
$$

while:

$$
C_3^{(1)}\neq C_3^{(2)}
$$

The adversary knows these relationships without knowing the secret key.

### Example

Suppose:

$$
K=101
$$

For:

$$
M^{(1)}=000
$$

the ciphertext is:

$$
C^{(1)}=011
$$

For:

$$
M^{(2)}=001
$$

the ciphertext is:

$$
C^{(2)}=010
$$

The first two ciphertext bits are identical.

The final bit changes.

This relationship always holds for this cipher.

---

## 13.2 Distinguishing Advantage

The lecturer simplifies the probability calculation by comparing against independent random ciphertext bits.

There are three conditions:

1. The first ciphertext bits must match.
2. The second ciphertext bits must match.
3. The third ciphertext bits must differ.

For independent random bits, each condition has probability:

$$
\frac12
$$

The probability that all three conditions hold is:

$$
\frac12\cdot\frac12\cdot\frac12
$$

$$
=\frac18
$$

In the real cipher, the conditions always hold.

Therefore, under this simplified calculation:

$$
\operatorname{Adv}(A)
=
1-\frac18
$$

$$
\boxed{
\operatorname{Adv}(A)=\frac78
}
$$

### Important Note

The lecturer explicitly simplifies the ideal world to independent random bits for this exercise.

The formal PRP ideal world is a random permutation, so the exact PRP probability is different.

The lecturer states that students do not need to calculate the more complicated permutation probability for this example.

The important idea is that predictable relationships between plaintexts and ciphertexts allow distinguishing attacks.

# 14. Diffusion and Confusion

The lecturer introduces two important cryptographic design principles associated with Claude Shannon.

These principles explain why the previous toy cipher is insecure.

## 14.1 Diffusion

Diffusion means that a small change in the input should affect many output bits.

For example, changing a single plaintext bit should cause widespread changes in the ciphertext.

The slides mention the strict avalanche criterion.

Under this criterion, flipping one input bit should cause each output bit to flip with probability approximately:

$$
\frac12
$$

### Example

Consider two plaintexts that differ in one bit:

```text
Plaintext 1: 10110010
Plaintext 2: 10110011
```

A cipher with good diffusion should produce ciphertexts with changes spread across many positions.

This example is illustrative, not the output of a particular cipher.

### Why Diffusion Matters

If changing one input bit always changes only one predictable output bit, an adversary can exploit this relationship.

Diffusion helps spread the influence of input changes across the ciphertext.

---

## 14.2 Confusion

Confusion means that the secret key should influence the ciphertext in a complex, nonlinear way.

The relationship between the key and the ciphertext should not be simple or predictable.

The slides emphasize that each ciphertext bit should depend on the entire key.

### Difference Between Diffusion and Confusion

| Concept | Meaning |
|---|---|
| Diffusion | Spread the effect of input changes across many output bits |
| Confusion | Make the relationship between key and output complex and nonlinear |

The lecturer uses these principles to motivate the need for nonlinear operations in cryptographic constructions.

---

# 15. Linear and Affine Functions

The final part of the lecture explains why linear and affine functions alone cannot provide the required security.

## 15.1 Linear Functions

A linear function has the form:

$$
F(x)=Lx
$$

where $L$ is a matrix.

It satisfies:

$$
F(x+\Delta x)=F(x)+F(\Delta x)
$$

This means the effect of an input difference can be calculated independently of the starting input.

---

## 15.2 Affine Functions

An affine function has the form:

$$
F(x)=Lx+c
$$

where $c$ is a constant.

For an affine function:

$$
F(x+\Delta x)-F(x)=L\Delta x
$$

Therefore, applying the same input difference always produces the same output difference.

Over binary vectors, addition is XOR.

---

## 15.3 Why the Toy Block Cipher Is Insecure

Recall the toy cipher:

$$
E_K(M)=P(M)\oplus K'
$$

where:

- $P$ swaps the first two bit positions.
- $K'$ represents the correspondingly arranged key bits.

Consider two messages:

$$
M
$$

and:

$$
M'
$$

Their ciphertexts satisfy:

$$
E_K(M)\oplus E_K(M')
$$

Substituting:

$$
=
(P(M)\oplus K')
\oplus
(P(M')\oplus K')
$$

The key cancels:

$$
K'\oplus K'=0
$$

Therefore:

$$
\boxed{
E_K(M)\oplus E_K(M')
=
P(M\oplus M')
}
$$

The ciphertext difference depends only on the plaintext difference.

It does not depend on the secret key.

Consequently, an adversary can predict relationships between ciphertexts without knowing the key.

This makes the toy cipher insecure.

---

## 15.4 Nonlinear Functions

To avoid predictable relationships, cryptographic constructions require nonlinear operations.

The lecturer briefly discusses nonlinear arithmetic functions and lookup tables.

The idea is that changing an input should not result in a simple, predictable change in the output.

Nonlinear operations are essential for the confusion property.

The lecture ends by motivating the use of nonlinear functions in secure cryptographic algorithms.

The detailed block cipher constructions are discussed in later material.

# 16. Stream Cipher vs. Block Cipher

Both are symmetric encryption primitives, but they operate differently.

| Property | Stream cipher | Block cipher |
|---|---|---|
| Main operation | Generates a keystream and combines it with plaintext | Directly transforms fixed-size plaintext blocks |
| Typical encryption | $C=M\oplus L$ | $C=E_K(M)$ |
| Output length | Keystream can be extended | One fixed-size block per primitive call |
| Ideal security model | Random bits | Random permutation |
| Security notion | PRG security | PRP security |
| Example | ChaCha | AES |

## Can a Stream Cipher Be a Permutation?

Yes.

For a fixed keystream $L$, stream cipher encryption is:

$$
E_L(M)=M\oplus L
$$

Since XOR is invertible, this mapping is a permutation over messages of the same length.

However, the PRG that generates $L$ does not have to be a permutation.

Different seeds may produce identical keystreams.

### Important Distinction

- A block cipher must be a permutation for each fixed key.
- A PRG does not have to be a permutation.
- XOR encryption with a fixed keystream is a permutation.

This does not mean that the same keystream should be reused for different messages.

Keystream reuse is insecure.

---

# 17. Summary of Security Notions

| Security notion | Real world | Ideal world | Adversary's goal |
|---|---|---|---|
| PRG | Pseudorandom output | Truly random bits | Distinguish PRG output from random |
| PRP | Real block cipher | Random permutation | Distinguish block cipher from random permutation |
| Strong PRP | Real encryption and decryption | Random permutation and its inverse | Distinguish the two worlds using encryption and decryption queries |

The central principle behind all three notions is computational indistinguishability.

A construction is secure when no efficient adversary can distinguish it from its corresponding ideal world with non-negligible advantage.

# Final Takeaway

The central idea of Lecture 3 is that modern cryptography relies on computational indistinguishability.

A PRG should generate outputs that an efficient adversary cannot distinguish from random bits.

A block cipher should behave like a uniformly random permutation.

Security is evaluated using distinguishing games and adversarial advantage.

The toy PRG and toy block cipher demonstrate that simple algebraic relationships, output biases, or predictable ciphertext differences can make a cryptographic construction insecure.

Secure cryptographic designs therefore need carefully constructed operations that provide diffusion, confusion, and resistance to efficient distinguishing attacks.
