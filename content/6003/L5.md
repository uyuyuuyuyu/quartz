# Lecture 5: Block Ciphers, DES, AES, and Encryption Schemes

## 1. Block Cipher Review

A block cipher encrypts a fixed-size plaintext block into a ciphertext block of the same size using a secret key.

$$
E_K:\{0,1\}^n\rightarrow\{0,1\}^n
$$

For every fixed key $K$, encryption must be a **permutation**, meaning every plaintext maps to a unique ciphertext and decryption is possible.

### 1.1 Security Definition

A secure block cipher should be computationally indistinguishable from a uniformly random permutation.

An adversary can submit plaintexts and observe their ciphertexts. The adversary should not be able to distinguish the real block cipher from a random permutation.

**Stream cipher vs. block cipher:**

| Stream Cipher | Block Cipher |
|---|---|
| Generates a potentially long keystream | Encrypts fixed-size blocks |
| Ideal output is uniformly random bits | Ideal behavior is a uniformly random permutation |
| Keystream is XORed with plaintext | Maps plaintext blocks to ciphertext blocks |
| Generates a pseudorandom bit sequence | Must be invertible for every key |

### 1.2 Shannon's Principles

Two principles are essential for constructing secure block ciphers.

**Diffusion**

A small change in the plaintext should spread across many ciphertext bits.

For example, changing one input bit should potentially affect many output bits.

**Confusion**

The relationship between the secret key, plaintext, and ciphertext should be complex and nonlinear.

A linear transformation alone is insufficient because changes in its output can be predicted from changes in its input.

Secure block ciphers combine nonlinear operations with operations that spread changes throughout the state.

## 2. Feistel Networks

A Feistel network divides a block into two halves:

$$
M=(L_0,R_0)
$$

Each round applies a function $F_i$ to one half and combines its result with the other half.

A conventional Feistel round is:

$$
L_{i+1}=R_i
$$

$$
R_{i+1}=L_i\oplus F_i(R_i)
$$

The round function is repeated multiple times.

### 2.1 Why Two Rounds Are Insufficient

Consider two plaintexts that have identical right halves but different left halves:

$$
M=(L_0,R_0)
$$

$$
M'=(L'_0,R_0)
$$

Since the first round function receives the same input, it produces the same output.

After two rounds:

$$
L_2=L_0\oplus F_1(R_0)
$$

$$
L'_2=L'_0\oplus F_1(R_0)
$$

XORing the two resulting halves gives:

$$
\boxed{L_2\oplus L'_2=L_0\oplus L'_0}
$$

The attacker can therefore predict a relationship between the ciphertexts.

For a random permutation, such a relationship would occur only with a small probability.

This allows an attacker to distinguish a two-round Feistel network from a random permutation.

### 2.2 Number of Rounds

The lecture gives the following results for Feistel networks with sufficiently strong round functions:

| Rounds | Security |
|---|---|
| 2 | Insufficient |
| 3 | Can be secure against encryption-only queries |
| 4 | Can be secure even when decryption queries are allowed |

These results assume appropriate strong round functions. They do not mean that every arbitrary four-round Feistel network is secure.

## 3. Data Encryption Standard (DES)

DES was an early standardized block cipher developed in the 1970s.

Its main properties are:

| Property | DES |
|---|---|
| Block size | 64 bits |
| Nominal key size | 64 bits |
| Effective key size | 56 bits |
| Structure | Feistel network |
| Number of rounds | 16 |
| Round-key size | 48 bits |

Eight bits of the nominal 64-bit key are parity bits rather than secret key material.

Therefore, DES has only:

$$
2^{56}
$$

possible effective keys.

### 3.1 DES Round Function

DES uses a relatively simple round function that is repeated 16 times.

Each round processes a 32-bit input and produces a 32-bit output.

The main operations are:

1. **Expansion:** Expand the 32-bit input into 48 bits by repeating selected bits.
2. **Key mixing:** XOR the expanded value with a 48-bit round key.
3. **S-box substitution:** Use eight S-boxes, each mapping 6 input bits to 4 output bits.
4. **Permutation:** Rearrange the resulting 32 bits to distribute changes into subsequent rounds.

The S-boxes provide nonlinearity, while the expansion and permutation help spread changes across the state.

DES uses 16 rounds because its individual round function is relatively simple. More rounds are required to obtain sufficiently complex overall behavior.

### 3.2 DES Weaknesses

**Short key length**

DES has only 56 bits of effective key material.

An exhaustive key search requires testing up to:

$$
2^{56}
$$

keys.

Improvements in computing power and specialized hardware eventually made this practical.

**Cryptanalytic attacks**

Research on DES led to important cryptanalytic techniques, including:

- Differential cryptanalysis
- Linear cryptanalysis

The lecturer emphasizes that the main practical problem with DES was its short key rather than these theoretical attacks.

**Complementation property**

DES has the property:

$$
\boxed{E_{\overline K}(\overline M)=\overline{E_K(M)}}
$$

where the bar denotes bitwise complementation.

This property follows from the structure of DES and its key schedule.

The lecturer mentions it as an interesting property but does not require memorizing its detailed derivation.

> [!important] Exam Focus
> Understand the DES structure, its effective key size, and why its short key made it insecure.
>
> Memorizing the internal permutation tables and S-box values is unnecessary.

## 4. Double DES

One attempt to strengthen DES was to encrypt each message twice using two independent keys.

$$
\boxed{C=E_{K_2}(E_{K_1}(M))}
$$

Each key contains 56 bits.

The total key material is therefore:

$$
56+56=112\text{ bits}
$$

A naive exhaustive search over both keys requires:

$$
2^{112}
$$

key combinations.

However, Double DES is vulnerable to a **meet-in-the-middle attack**.

### 4.1 Meet-in-the-Middle Attack

Assume the attacker knows a plaintext-ciphertext pair:

$$
(M,C)
$$

Define the intermediate state:

$$
S=E_{K_1}(M)
$$

Since:

$$
C=E_{K_2}(S)
$$

we also have:

$$
S=D_{K_2}(C)
$$

Therefore, the correct keys satisfy:

$$
\boxed{E_{K_1}(M)=D_{K_2}(C)}
$$

The attack proceeds as follows.

**Step 1: Forward computation**

For every possible $K_1$, calculate:

$$
S=E_{K_1}(M)
$$

Store the intermediate state and its corresponding key in a table.

The table contains approximately:

$$
2^{56}
$$

entries.

**Step 2: Backward computation**

For every possible $K_2$, calculate:

$$
T=D_{K_2}(C)
$$

Check whether $T$ appears in the forward table.

If:

$$
S=T
$$

the corresponding keys form a candidate key pair.

**Step 3: Verify candidates**

Some intermediate states may match accidentally.

Use another known plaintext-ciphertext pair:

$$
(M',C')
$$

to test the candidate keys.

A candidate is consistent with both pairs when:

$$
E_{K_2}(E_{K_1}(M'))=C'
$$

Additional pairs can be used if necessary.

### 4.2 Attack Complexity

The forward computation requires approximately:

$$
2^{56}
$$

operations.

The backward computation requires approximately:

$$
2^{56}
$$

operations.

The total is:

$$
2^{56}+2^{56}
$$

Thus:

$$
\boxed{T\approx2^{57}}
$$

The attack also requires approximately $2^{56}$ table entries.

The lecturer notes that this memory requirement is extremely large, and practical attacks may use time-memory trade-offs instead.

> [!important] Key Takeaway
> Double encryption does not necessarily double the effective security.
>
> The attacker can compute independent parts of the encryption separately and match them at an intermediate state.

## 5. Triple DES

Triple DES applies DES three times using three independent keys.

The lecture analyzes the conceptual construction:

$$
C=E_{K_3}(E_{K_2}(E_{K_1}(M)))
$$

The commonly standardized Triple DES uses an encrypt-decrypt-encrypt arrangement. The same basic meet-in-the-middle reasoning applies.

### 5.1 Why Triple DES Is More Resistant

Each key has 56 bits:

$$
K_1,K_2,K_3
$$

The total key material is:

$$
3\times56=168\text{ bits}
$$

Consider splitting the encryption after the second operation.

The forward computation is:

$$
S=E_{K_2}(E_{K_1}(M))
$$

The backward computation is:

$$
T=D_{K_3}(C)
$$

To compute every possible forward state, the attacker must try every combination of $K_1$ and $K_2$:

$$
2^{56}\times2^{56}=2^{112}
$$

The backward direction requires approximately:

$$
2^{56}
$$

operations.

The basic meet-in-the-middle attack therefore requires approximately:

$$
\boxed{2^{112}}
$$

work.

Triple DES consequently provides substantially more resistance to this attack than Double DES.

### 5.2 Why Not Use Three Small Tables?

The lecturer addresses an important question:

Why can the attacker not create three separate tables, each containing only $2^{56}$ entries?

The problem is that the input to the middle encryption depends on the first secret key.

To compute:

$$
E_{K_2}(E_{K_1}(M))
$$

the attacker must consider every combination of $K_1$ and $K_2$.

The operations cannot be separated into three completely independent computations with known starting points.

### 5.3 Multiple Encryption in General

For independent $k$-bit keys, the lecture analyzes the basic meet-in-the-middle attack on repeated encryption.

| Number of Encryptions | Total Key Material | Approximate MITM Work |
|---|---|---|
| 1 | $k$ | $2^k$ |
| 2 | $2k$ | $2^{k+1}$ |
| 3 | $3k$ | $2^{2k}$ |
| 4 | $4k$ | $2^{2k}$ |
| 5 | $5k$ | $2^{3k}$ |
| 6 | $6k$ | $2^{3k}$ |

These values describe the basic attack discussed in the lecture, not necessarily the optimal attack against every construction.

For four encryptions, the attacker can split the construction into two independent halves:

$$
E_{K_2}(E_{K_1}(M))
=
D_{K_3}(D_{K_4}(C))
$$

Each side requires trying all combinations of two keys.

Hence, the basic attack has approximately:

$$
2^{2k}
$$

work per side.

> [!important] Important Principle
> For multiple encryption, identify where the construction can be split into independent computations and determine how many key combinations each side requires.

## 6. Advanced Encryption Standard (AES)

AES was developed to replace DES and Triple DES with a faster and more secure block cipher.

The winning design in the NIST competition was Rijndael.

AES is a substitution-permutation network rather than a Feistel network.

### 6.1 AES Parameters

| Version | Block Size | Key Size | Rounds |
|---|---|---|---|
| AES-128 | 128 bits | 128 bits | 10 |
| AES-192 | 128 bits | 192 bits | 12 |
| AES-256 | 128 bits | 256 bits | 14 |

All AES versions use 128-bit blocks.

Only the key length and number of rounds differ.

### 6.2 AES State

AES represents its 128-bit state as a matrix of 16 bytes:

$$
\begin{bmatrix}
s_{0,0}&s_{0,1}&s_{0,2}&s_{0,3}\\
s_{1,0}&s_{1,1}&s_{1,2}&s_{1,3}\\
s_{2,0}&s_{2,1}&s_{2,2}&s_{2,3}\\
s_{3,0}&s_{3,1}&s_{3,2}&s_{3,3}
\end{bmatrix}
$$

Each byte contains 8 bits.

The total state size is:

$$
16\times8=128\text{ bits}
$$

### 6.3 AES Round Structure

An ordinary AES round consists of four operations:

$$
\boxed{
\text{SubBytes}
\rightarrow
\text{ShiftRows}
\rightarrow
\text{MixColumns}
\rightarrow
\text{AddRoundKey}
}
$$

AES also performs an initial AddRoundKey operation before the first round.

The final round omits MixColumns.

For AES-128, the round keys are:

$$
K_0,K_1,\ldots,K_{10}
$$

There are 11 round keys in total.

### 6.4 SubBytes

SubBytes replaces each byte using an S-box.

$$
S:\{0,1\}^{8}\rightarrow\{0,1\}^{8}
$$

The S-box is a lookup table containing 256 entries.

It maps each possible input byte to an output byte.

SubBytes is the nonlinear component of AES.

Its purpose is to provide confusion and make the relationship between input changes and output changes unpredictable.

However, SubBytes operates independently on each byte.

A change in one byte does not directly affect any other byte.

Therefore, SubBytes alone does not provide sufficient diffusion.

### 6.5 ShiftRows

ShiftRows cyclically rotates the rows of the state.

| Row | Rotation |
|---|---|
| 0 | No rotation |
| 1 | Left by 1 byte |
| 2 | Left by 2 bytes |
| 3 | Left by 3 bytes |

ShiftRows rearranges byte positions without changing their values.

Its purpose is to move bytes into different columns so that subsequent MixColumns operations spread changes across the state.

### 6.6 MixColumns

MixColumns mixes the four bytes within each column.

Its purpose is to spread changes from one byte to other bytes in the same column.

The lecturer highlights the property:

$$
\boxed{a+b\geq5}
$$

where:

- $a$ is the number of changed input bytes.
- $b$ is the number of changed output bytes.

For example, if exactly one input byte changes:

$$
a=1
$$

then:

$$
b=4
$$

All four output bytes in that column must change.

The lecture does not require memorizing the internal matrix arithmetic of MixColumns.

### 6.7 Why ShiftRows and MixColumns Are Both Necessary

Consider changing a single byte.

After SubBytes, the change remains within that byte.

After MixColumns, the change spreads to the four bytes of its column.

In the next round, ShiftRows moves these affected bytes into different columns.

The following MixColumns operation then spreads the changes throughout the state.

Thus:

$$
\boxed{
\text{ShiftRows}+\text{MixColumns}
\Rightarrow\text{Diffusion across the state}
}
$$

Without ShiftRows, changes would remain within their original columns.

Without MixColumns, ShiftRows would only move the affected bytes without spreading the change to other bytes.

Both operations are necessary.

### 6.8 AddRoundKey

AddRoundKey XORs the state with a round key:

$$
\boxed{S'=S\oplus K_i}
$$

This incorporates the secret key into the encryption process.

Without the round-key additions, the remaining AES operations would be publicly computable and would provide no secret-key protection.

### 6.9 Summary of AES Operations

| Operation | Main Purpose |
|---|---|
| SubBytes | Nonlinearity and confusion |
| ShiftRows | Redistribute bytes across columns |
| MixColumns | Spread changes within columns |
| AddRoundKey | Mix the secret key into the state |

The lecture emphasizes understanding the purpose of each operation rather than memorizing its internal implementation.

## 7. AES Implementation and Timing Attacks

The lecture explains that a mathematically secure cipher can still leak information through its implementation.

An example is a software implementation of AES using S-box lookup tables.

A processor may access a table entry more quickly if that entry is already in its cache.

Consequently, the execution time can depend on which table entries are accessed.

Since these accesses depend on internal values involving the secret key, timing differences can reveal information about the key.

An attacker may measure encryption times and use these differences to recover secret information.

This is a **timing side-channel attack**.

### Hardware Support

Modern processors provide dedicated AES instructions.

These instructions offer two important benefits:

1. Faster AES encryption.
2. Protection against the secret-dependent lookup timings discussed in the lecture.

Dedicated AES hardware instructions can perform the relevant operations in constant time with respect to the input values.

The lecturer emphasizes that secure implementation matters in addition to the mathematical security of the algorithm.

## 8. Encryption Schemes

A block cipher encrypts only one fixed-size block.

For example, AES processes:

$$
128\text{-bit plaintext}
\rightarrow
128\text{-bit ciphertext}
$$

However, real messages may be much shorter or much longer.

An encryption scheme specifies how to use a block cipher to encrypt messages of variable length.

### 8.1 Deterministic Encryption

Deterministic encryption always produces the same ciphertext for the same plaintext under the same key.

$$
E_K(M)=C
$$

Encrypting $M$ again with the same key produces the same $C$.

This can reveal repeated messages.

For example, if the message "yes" is encrypted twice under the same key, an observer may recognize that the two ciphertexts correspond to identical plaintexts.

The lecturer notes that deterministic encryption can still be useful in some settings where plaintexts already contain sufficient randomness.

### 8.2 Nonce-Based Encryption

Nonce stands for:

**Number used once.**

A nonce is an additional input that must not repeat under the same key.

Encryption takes the form:

$$
C=E_K(N,M)
$$

where:

- $K$ is the secret key.
- $N$ is the nonce.
- $M$ is the plaintext.

The nonce can be a counter or another value that does not repeat.

Different nonces allow the same plaintext to produce different ciphertexts.

The nonce is generally sent alongside the ciphertext because it is needed for decryption.

The nonce does not need to be secret.

### 8.3 Randomized Encryption

In randomized encryption, the encryption algorithm chooses a random initial value internally.

It uses this value to encrypt the plaintext and returns the value alongside the ciphertext.

The key distinction is:

| Nonce-Based Encryption | Randomized Encryption |
|---|---|
| Caller supplies the nonce | Algorithm generates a random value |
| Nonce must satisfy the scheme's uniqueness requirements | Random value must satisfy the scheme's randomness requirements |
| Value is available for decryption | Generated value is returned for decryption |

The purpose of both approaches is to avoid revealing repeated messages through identical ciphertexts.

## 9. Electronic Codebook (ECB) Mode

ECB is the simplest mode of operation for a block cipher.

It divides the plaintext into fixed-size blocks:

$$
M=M_1\|M_2\|\cdots\|M_n
$$

Each block is encrypted independently:

$$
\boxed{C_i=E_K(M_i)}
$$

Decryption is:

$$
\boxed{M_i=D_K(C_i)}
$$

### 9.1 Padding

A block cipher requires fixed-size inputs.

If a message is not a multiple of the block size, ECB needs padding.

For AES, the block size is 128 bits.

For example:

- A 128-bit message fits into one block.
- A 129-bit message needs to be extended to two blocks.
- A 10-bit message must be extended to fit a full block.

### 9.2 ECB Properties

| Property | ECB |
|---|---|
| Encryption parallelizable | Yes |
| Decryption parallelizable | Yes |
| Padding required | Yes, when message length is not block-aligned |
| Requires block cipher decryption | Yes |

### 9.3 Why ECB Is Insecure

ECB encrypts every block independently and deterministically.

Therefore:

$$
M_i=M_j
\implies
E_K(M_i)=E_K(M_j)
$$

Equivalently:

$$
\boxed{M_i=M_j\implies C_i=C_j}
$$

Identical plaintext blocks produce identical ciphertext blocks.

This reveals repetition patterns in the plaintext.

An attacker can exploit this by submitting a plaintext containing repeated blocks and checking whether the ciphertext contains repeated blocks.

Such patterns would be extremely unlikely in a sequence of independent uniformly random bits.

The lecturer also describes the familiar image-encryption example: when an image is encrypted using ECB, its visual structure may remain recognizable because identical plaintext blocks map to identical ciphertext blocks.

> [!important] Key Takeaway
> A secure block cipher does not make ECB a secure encryption scheme.

## 10. Counter (CTR) Mode

CTR mode uses a block cipher to generate a keystream.

Instead of encrypting plaintext blocks directly, it encrypts successive counter values.

The resulting keystream is XORed with the plaintext.

This makes CTR similar to a stream cipher.

### 10.1 Keystream Generation

Suppose the initial counter value is $N$.

The block cipher generates:

$$
S_1=E_K(N)
$$

$$
S_2=E_K(N+1)
$$

$$
S_3=E_K(N+2)
$$

In general:

$$
\boxed{S_i=E_K(N+i-1)}
$$

Each counter value should be distinct so that a keystream block is not reused under the same key.

### 10.2 CTR Encryption

Each plaintext block is XORed with the corresponding keystream block:

$$
\boxed{C_i=M_i\oplus S_i}
$$

For example:

$$
C_1=M_1\oplus E_K(N)
$$

$$
C_2=M_2\oplus E_K(N+1)
$$

$$
C_3=M_3\oplus E_K(N+2)
$$

### 10.3 CTR Decryption

Decryption uses the same keystream:

$$
M_i=C_i\oplus S_i
$$

This works because:

$$
\begin{aligned}
C_i\oplus S_i
&=(M_i\oplus S_i)\oplus S_i\\
&=M_i\oplus(S_i\oplus S_i)\\
&=M_i
\end{aligned}
$$

Since:

$$
S_i\oplus S_i=0
$$

we obtain:

$$
\boxed{M_i=C_i\oplus S_i}
$$

Encryption and decryption therefore use the same XOR operation.

CTR does not require the inverse block cipher $D_K$.

Only the forward encryption function $E_K$ is needed.

### 10.4 Advantages of CTR

CTR has several efficiency advantages:

- Encryption is parallelizable.
- Decryption is parallelizable.
- The inverse block cipher is unnecessary.
- Padding is unnecessary.
- It can encrypt messages of arbitrary length.

If the final plaintext block is shorter than the block size, only the required keystream bits are used.

For example, if the last message block contains five bits, the algorithm uses five bits of the corresponding keystream block and discards the rest.

### 10.5 Counter Reuse

The lecture concludes by explaining that CTR is secure only when used properly.

If the same key and initial counter are reused, the same keystream is generated.

Suppose:

$$
C_1=M_1\oplus S
$$

$$
C_2=M_2\oplus S
$$

Then:

$$
\begin{aligned}
C_1\oplus C_2
&=(M_1\oplus S)\oplus(M_2\oplus S)\\
&=M_1\oplus M_2
\end{aligned}
$$

Therefore:

$$
\boxed{C_1\oplus C_2=M_1\oplus M_2}
$$

The keystream cancels out.

This reveals a relationship between the plaintexts.

The lecture introduces nonce-based and randomized initialization as ways to avoid reusing the same keystream. The detailed treatment continues in the next lecture.

## 11. ECB vs. CTR

| Property | ECB | CTR |
|---|---|---|
| Encrypts plaintext blocks directly | Yes | No |
| Uses block cipher to generate a keystream | No | Yes |
| Requires padding | Yes | No |
| Encryption parallelizable | Yes | Yes |
| Decryption parallelizable | Yes | Yes |
| Requires inverse block cipher | Yes | No |
| Reveals repeated plaintext blocks | Yes | Not when used properly |
| Requires unique counter inputs | No | Yes |
| Provides secure encryption when properly initialized | No | Yes, under appropriate assumptions |

| Concept | Formula |
|---|---|
| Feistel round | $L_{i+1}=R_i$ |

The lecturer emphasizes that the quizzes will resemble the exercises, although they will be less time-consuming.

Explanations do not need to reproduce the lecture's wording exactly, but the reasoning and notation must be understandable.

Focus on being able to:

- Explain DES's structure and why its 56-bit key is insufficient.
- Construct a meet-in-the-middle attack using forward and backward computations.
- Calculate the basic attack complexity of Double DES, Triple DES, and multiple encryption.

- Explain and demonstrate why ECB reveals repeated plaintext blocks.
- Calculate CTR encryption and decryption using XOR.
- Explain why CTR must avoid keystream reuse.

The lecturer explicitly says that memorizing the DES permutation tables, AES S-box entries, and detailed MixColumns arithmetic is not necessary.

> [!summary] Lecture Takeaway
> Secure encryption requires both a secure underlying cipher and a secure way of using it.
>
> - **DES** illustrates the problem of insufficient key length.
> - **Meet-in-the-middle attacks** show why multiple encryption does not necessarily provide security proportional to total key material.
> - **AES** illustrates efficient block cipher construction using confusion, diffusion, and key mixing.
> - **ECB** demonstrates that a secure block cipher can be used insecurely.
> - **CTR** demonstrates how a block cipher can generate a keystream for efficient encryption, provided keystream reuse is avoided.
