# 1. Cryptography Recap

Cryptography protects communication and information against unauthorized access and modification.

## 1.1 Security Properties

The **CIA triad** consists of:

| Property | Description |
|---|---|
| Confidentiality | Prevent unauthorized access to information |
| Integrity | Prevent unauthorized modification of information |
| Availability | Ensure authorized users can access information when needed |

Additional security properties:

- **Authenticity:** Verify the identity of the communicating party.
- **Non-repudiation:** Prevent participants from denying actions or communications they performed.
- **Privacy:** Control the collection, access, and use of personal information.

## 1.2 Cryptographic Building Blocks

### Symmetric Cryptography

Both parties use the same secret key for encryption and decryption.

Example: AES.

$$
C=E_K(P)
$$

$$
P=D_K(C)
$$

Advantages:
- Fast encryption and decryption.
- Suitable for large amounts of data.

Disadvantage:
- Both parties must securely establish a shared secret key.

### Asymmetric Cryptography

Uses a public/private key pair.

Examples:
- RSA
- ECC

A sender can use the recipient's public key to protect information. Only the corresponding private key can decrypt it in a public-key encryption scheme.

Public-key techniques can help establish a shared symmetric key.

### Hash Functions

A hash function maps an input of arbitrary length to a fixed-length output.

$$
h=H(M)
$$

Important properties:
- One-way computation.
- Sensitive to changes in the input.
- Useful for integrity verification.

Examples:
- SHA-2
- SHA-3

A plain hash does not authenticate a sender by itself. Authentication requires an appropriate construction such as a MAC or digital signature.

## 1.3 Typical Secure Communication

Alice wants to send a large encrypted message to Bob.

1. Alice generates a symmetric secret key.
2. Alice protects the key using Bob's public key.
3. Bob recovers the symmetric key using his private key.
4. Alice and Bob use the symmetric key to encrypt and decrypt the actual data.

```text
Alice                         Bob

Generate symmetric key
          |
          v
Protect using
Bob's public key
          |
          v
Protected key -------------> Private key
                                  |
                                  v
                            Recover secret key

Both parties now have the shared secret key.

Alice encrypts data -------> Bob decrypts data
```

Modern protocols may use key-encapsulation or authenticated key-agreement mechanisms rather than directly encrypting the symmetric key.

# 2. Quantum Threat and Post-Quantum Cryptography

Traditional public-key cryptography relies on mathematical problems believed to be computationally difficult for classical computers.

| Algorithm | Mathematical foundation |
|---|---|
| RSA | Integer factorization |
| ECC | Discrete logarithm problem |

A sufficiently capable quantum computer running **Shor's algorithm** could undermine these mathematical foundations.

This motivates the development of **Post-Quantum Cryptography (PQC)**.

Examples discussed in the slides:

| Category | Algorithms |
|---|---|
| Key encapsulation | Kyber / ML-KEM, HQC |
| Digital signatures | Dilithium / ML-DSA, Falcon / FN-DSA, SPHINCS+ / SLH-DSA |

Post-quantum algorithms run on ordinary classical computers. Their purpose is to resist attacks from both classical and quantum computers.

> [!important] Connection to this lecture
> Even when an algorithm is mathematically secure, its implementation may still leak sensitive information.
>
> This applies to traditional cryptography and post-quantum cryptography alike.

# 3. Why Cyber-Physical Systems Create New Threats

Traditional cryptographic systems were often deployed in environments where attackers had limited physical access.

Modern cryptography is increasingly implemented in:

- IoT devices
- Smartphones
- Smartcards
- Automotive systems
- Medical devices
- Industrial controllers
- Embedded microcontrollers
- Security hardware

These systems have different computational capabilities and security protections.

A new problem arises because attackers may have physical access or proximity to devices that execute cryptographic algorithms.

Common IoT threats include:

1. Malware and viruses.
2. Counterfeit components.
3. Physical attacks.
4. Hardware Trojans.

A hardware Trojan is a malicious modification implemented using physical circuit components such as gates or wires.

Unlike ordinary software malware, a hardware Trojan cannot necessarily be removed through a software update.

This lecture focuses on attacks that exploit **unintentional physical information leakage**.

# 4. Side-Channel Analysis (SCA)

## 4.1 Definition

A **side-channel attack** extracts sensitive information by observing physical effects produced during the execution of a computation.

Cryptographic operations produce physical characteristics such as:

- Execution time
- Power consumption
- Electromagnetic radiation
- Acoustic emissions
- Optical emissions
- Cache activity
- Sensor measurements

These physical effects can depend on the secret data being processed.

Therefore:

$$
\text{Secret data}
\rightarrow
\text{Physical activity}
\rightarrow
\text{Information leakage}
$$

An attacker measures and analyzes this leakage to infer the secret.

## 4.2 Implementation Attack vs Mathematical Attack

Traditional cryptanalysis searches for weaknesses in the underlying cryptographic algorithm.

Side-channel analysis searches for information unintentionally exposed by the algorithm's implementation.

| Traditional cryptanalysis | Side-channel analysis |
|---|---|
| Studies mathematical weaknesses | Studies implementation leakage |
| Primarily analyzes cryptographic relationships | Analyzes physical measurements |
| May require a very large search space | Can recover keys through measurable leakage |
| Does not necessarily require hardware access | Often benefits from physical access |

> [!important] Fundamental Principle
> A mathematically secure cryptographic algorithm does not automatically guarantee a secure physical implementation.

## 4.3 The Combination Lock Analogy

Imagine trying to discover the combination of a mechanical lock.

**Brute-force approach:**

Try every possible combination.

**Side-channel approach:**

Listen to the sounds produced by the lock.

If the mechanism produces different sounds depending on whether a position is correct, the sound may reveal information about the combination.

The same principle applies to cryptographic hardware.

The implementation may unintentionally reveal secrets through timing, power consumption, or electromagnetic emissions.

## 4.4 Characteristics of Side-Channel Attacks

Side-channel attacks are often:

- Non-invasive.
- Observational or passive with respect to the physical leakage.
- Practical against embedded systems.
- Capable of recovering cryptographic keys.
- Useful for reverse engineering and other applications.

Some attacks also actively submit chosen inputs to the device while observing its physical response.

Non-invasive means the attacker does not need to physically modify or damage the internal circuit.

# 5. Smartphone PIN Side-Channel Example

The lecturer introduced SCA using smartphone PIN recovery.

When someone types on a smartphone, their fingers and hand cause small physical movements.

Smartphone sensors capture these movements.

Relevant sensors include:
- Accelerometer
- Gyroscope
- Rotation-vector sensor

Different digits can produce different movement patterns.

For example:

```text
PIN: 0 - 8 - 5 - 2
```

Each digit can produce a different motion signature.

An attacker who obtains the sensor measurements could train a machine-learning model to infer the entered PIN.

The lecture presents results showing that sensor information can substantially improve guessing accuracy compared with random guessing.

The exact success rate depends on the training and evaluation conditions.

### Why this is a side-channel attack

The user did not intentionally transmit their PIN through the sensors.

However:

```text
User enters PIN
       |
       v
Physical phone movement
       |
       v
Sensor measurements
       |
       v
Machine-learning analysis
       |
       v
PIN inference
```

The sensitive information leaks unintentionally through the physical behavior of the device.

# 6. History and Real-World Examples

## 6.1 Historical Background

Early examples of side-channel leakage include:

- WWI battlefield telephone interception through electrical signals in the ground.
- Electromagnetic interception of electronic equipment.
- Radiation from CRT monitors.
- TEMPEST research into compromising emanations and shielding.

In the 1990s, Paul Kocher's research demonstrated how execution timing and power consumption could reveal cryptographic secrets.

This helped establish modern cryptographic side-channel analysis.

## 6.2 Real-World Examples

### KeeLoq

A keyless car-entry system.

Researchers demonstrated side-channel key extraction, including recovery of manufacturer-level secrets.

### MIFARE DESFire

A smartcard system used in applications such as access control and public transportation.

Power-analysis techniques were demonstrated against vulnerable implementations.

### FPGA Bitstream Encryption

FPGA configuration data may be encrypted to protect intellectual property.

If an attacker extracts the decryption key through side-channel analysis, they may recover or modify the protected configuration.

### Cryptocurrency Hardware Wallets

Hardware wallets store sensitive cryptographic information while remaining isolated from ordinary online systems.

Physical side-channel attacks may compromise vulnerable implementations despite that network isolation.

> [!important]
> Physical isolation from the internet does not necessarily prevent attacks based on physical information leakage.

# 7. Side-Channel Attack Workflow

The lecture identifies four major stages.

```text
Trace Measurement
        |
        v
Pre-processing
        |
        v
Leakage Identification
        |
        v
Leakage Exploitation
        |
        v
Key Recovery
```

## Stage 1: Trace Measurement

Collect physical observations from the target.

Examples:
- Timing measurements.
- Power traces.
- Electromagnetic traces.

A **trace** is a sequence of measured values recorded during an operation.

## Stage 2: Pre-processing

Prepare the collected data for analysis.

Possible operations:
- Filtering.
- Noise reduction.
- Alignment.
- Normalization.

## Stage 3: Leakage Identification

Identify which measurements or time positions contain useful secret-dependent information.

For example, locate the part of an AES trace corresponding to an S-box operation.

## Stage 4: Leakage Exploitation

Apply suitable analytical techniques to the leakage.

Examples:
- Visual inspection.
- Statistical hypothesis testing.
- Machine learning.

The objective may be to recover a secret key.

# 9. Timing Attacks

## 9.1 Principle

A timing attack exploits execution-time differences caused by the data being processed.

$$
T=f(\text{processed data})
$$

If execution time depends on a secret value, timing measurements may reveal information about that secret.

Possible causes include:
- Conditional branches.
- Different instruction sequences.
- Early termination.
- Different memory accesses.
- Cache effects.

Timing attacks can sometimes be performed remotely.

## 9.2 PIN Verification Example

Consider a program that compares a four-digit PIN.

A naïve implementation checks the digits sequentially and returns immediately after the first mismatch.

```python
def check_pin(guess, secret):
    for i in range(4):
        if guess[i] != secret[i]:
            return False

    return True
```

Suppose the correct PIN is:

```text
5824
```

Different guesses require different numbers of comparisons.

| Guess | Correct prefix | Comparisons before rejection |
|---|---:|---:|
| 1234 | 0 digits | 1 |
| 5234 | 1 digit | 2 |
| 5834 | 2 digits | 3 |
| 5825 | 3 digits | 4 |

More matching prefix digits result in more comparisons.

Therefore, the execution time may reveal how much of the PIN is correct.

### Search-Space Reduction

A four-digit decimal PIN has:

$$
10^4=10,000
$$

possible combinations.

If the first two digits are discovered:

$$
10^2=100
$$

possibilities remain.

The side channel reduces the amount of guessing required.

## 9.3 Characteristics

| Property | Timing attack |
|---|---|
| Target preparation | None to low |
| Equipment cost | Low |
| Expertise | Low |
| Leakage information | Generally low |
| Noise | Can be high |
| Physical access | Not necessarily required |

These are the qualitative characteristics presented in the lecture.

> [!important] Key Idea
> Execution time should not expose secret-dependent differences that an attacker can exploit.

# 10. Power Consumption Leakage

Power analysis is one of the major topics of this lecture.

## 10.1 Why Digital Circuits Consume Power

Modern digital circuits are commonly implemented using CMOS technology.

CMOS circuits contain transistors and capacitive loads.

When electrical signals transition between logical states, internal capacitances charge or discharge.

Examples:

$$
0\rightarrow1
$$

$$
1\rightarrow0
$$

These transitions produce electrical activity and dynamic power consumption.

Consequently:

$$
\text{Switching activity}
\rightarrow
\text{Power consumption}
$$

If the switching activity depends on secret data, power consumption can reveal information about that data.

## 10.2 Why CMOS Leaks Information

Suppose a circuit processes different binary values.

Different values may require different transistor-switching patterns.

An attacker measuring power consumption may therefore observe variations related to the processed data.

A single CMOS gate produces a small effect.

However, a processor contains many gates, and their collective switching activity can create measurable leakage.

```text
Secret-dependent computation
             |
             v
      CMOS switching
             |
             v
      Current consumption
             |
             v
       Measured power
             |
             v
      Information leakage
```

# 11. Power Measurement Techniques

Two measurement approaches are discussed.

## 11.1 Low-Side Measurement

A small resistor is placed between the target device and ground.

The voltage drop across the resistor is measured.

Using Ohm's law:

$$
V=IR
$$

The measured voltage provides information about the current flowing through the device.

Advantages:
- Common approach.
- Relatively low measurement noise.

Disadvantages:
- Small resistor produces a small voltage signal.
- Signal amplification may be needed.

## 11.2 High-Side Measurement

A resistor is placed between the power supply and the device.

Advantages:
- Potentially stronger measured signal.

Disadvantages:
- More exposure to power-supply noise.

## 11.3 Comparison

| Feature | Low-side | High-side |
|---|---|---|
| Measurement location | Between device and ground | Between supply and device |
| Typical measured signal | Smaller | Potentially larger |
| Noise | Relatively low | Potentially higher |
| Main consideration | Weak signal | Supply noise |

The best technique depends on the target and measurement setup.

The lecturer emphasized that the important factor is the **signal-to-noise ratio**.

---

# 12. Signal-to-Noise Ratio (SNR)

SNR describes the strength of useful leakage relative to unwanted noise.

Conceptually:

$$
SNR\propto
\frac{\text{Useful leakage signal}}
{\text{Noise}}
$$

For an attacker:

$$
\text{High SNR}
\Rightarrow
\text{Easier leakage exploitation}
$$

For a defender:

$$
\text{Low SNR}
\Rightarrow
\text{More difficult attack}
$$

Noise may come from:
- Other processing activity.
- Measurement equipment.
- Power-supply variations.
- Environmental interference.
- Misalignment between traces.

> [!important]
> SNR is central to both side-channel attacks and side-channel countermeasures.

# 13. Electromagnetic (EM) Leakage

## 13.1 Principle

Current flowing through an electronic circuit produces electromagnetic fields.

When computational activity changes the current, the associated electromagnetic emissions also change.

```text
Secret-dependent operation
             |
             v
      Changing current
             |
             v
    Electromagnetic field
             |
             v
       EM measurement
             |
             v
     Secret information
```

An attacker can place an electromagnetic probe near the device to capture these emissions.

## 13.2 EM Measurement Setup

A typical measurement setup includes:

```text
Target device
     |
     v
   EM probe
     |
     v
Pre-amplifier / Filters
     |
     v
 Oscilloscope
     |
     v
Computer / Trace storage
     |
     v
Leakage analysis
```

The probe captures electromagnetic emissions while the device performs cryptographic computations.

## 13.3 Why EM Can Be Useful

Power measurements may capture activity from the entire device.

For example:

$$
P_{\text{total}}
=
P_{\text{CPU}}
+
P_{\text{memory}}
+
P_{\text{crypto}}
+
P_{\text{other}}
$$

An EM probe can sometimes focus on a smaller physical region.

This allows the attacker to concentrate on the cryptographic component while reducing unrelated activity.

Therefore, localized EM measurements may provide higher SNR.

## 13.4 Random-Number Generator Example

The lecturer presented an EM trace from a random-number generator.

The measurement contained recognizable patterns for:

$$
0\rightarrow1
$$

and:

$$
1\rightarrow0
$$

If these transitions can be distinguished, the generated bits may be reconstructed from the measured trace.

This demonstrates how strong physical leakage can directly expose sensitive values.

## 13.5 Characteristics

| Property | EM measurement |
|---|---|
| Target preparation | Low |
| Equipment cost | Moderate |
| Expertise | Moderate |
| Leakage information | Potentially high |
| Noise | Potentially low with localization |
| Physical access | Usually required |

# 14. Other Side Channels

Physical information leakage is not restricted to power, EM, and timing.

Examples include:

### Acoustic Leakage

Sounds produced during computation can reveal information.

The lecturer described a 3D printer whose motor movements produce distinguishable acoustic patterns.

These sounds may reveal information about the object being manufactured.

### Optical Leakage

Electronic circuits can emit light or photons associated with their activity.

Specialized optical measurements may reveal information about internal processing.

### Cache-Timing Leakage

Memory-access patterns influence cache behavior.

If those patterns depend on secret information, the resulting timing differences may be exploitable.

### Software-Accessible Power Measurements

Modern processors may expose energy measurements through software interfaces.

An example presented in the lecture is **Intel RAPL (Running Average Power Limit)**.

RAPL provides information used for processor power management.

The lecture discusses the PLATYPUS attack as an example of security risks associated with software-accessible energy measurements.

> [!important]
> Some side-channel attacks can exploit hardware information without directly connecting physical measurement equipment to the target.

# 15. Three Categories of Side-Channel Analysis

The lecture identifies three principal categories.

| Type | Principle | Example |
|---|---|---|
| Simple SCA | Direct observation of traces | RSA SPA |
| Non-profiled SCA | Statistical analysis without a known-key training device | AES CPA |
| Profiled SCA | Train a model using known secrets | Template attacks, machine learning |

## 15.1 Simple SCA

The attacker visually examines one or a few traces.

Distinct physical patterns may directly reveal sensitive information.

Examples:
- RSA square-and-multiply.
- Detecting the number of operations.
- Recognizing secret-dependent execution paths.

## 15.2 Non-Profiled SCA

The attacker collects many traces and performs statistical analysis.

The secret key is unknown.

The attacker constructs key hypotheses and determines which candidate best explains the measured leakage.

Common techniques:
- Differential Power Analysis.
- Correlation Power Analysis.
- Difference of Means.
- Mutual Information.

The lecturer compares this conceptually to unsupervised/statistical inference.

## 15.3 Profiled SCA

The attacker possesses a training device with known or controllable secrets.

They collect labeled measurements and train a statistical or machine-learning model.

The trained model is then applied to a target device.

This is conceptually similar to supervised learning.

# 16. Simple Power Analysis (SPA)

## 16.1 Principle

SPA extracts sensitive information by directly examining measurable patterns in a power trace.

Unlike statistical attacks, it may only require one trace.

The main example is RSA exponentiation.

---

# 17. RSA Recap

RSA is an asymmetric cryptographic algorithm.

Choose two large prime numbers:

$$
p,q
$$

Compute:

$$
n=pq
$$

Euler's totient for this construction is:

$$
\phi(n)=(p-1)(q-1)
$$

Choose public exponent $e$ and private exponent $d$ such that:

$$
ed\equiv1\pmod{\phi(n)}
$$

The public key is:

$$
(n,e)
$$

The private exponent is:

$$
d
$$

Encryption:

$$
C=M^e\bmod n
$$

Decryption:

$$
M=C^d\bmod n
$$

RSA decryption requires modular exponentiation involving a potentially large exponent.

Efficient implementations use algorithms such as **square-and-multiply**.

---

# 18. Square-and-Multiply Algorithm

## 18.1 Why It Is Needed

Directly computing:

$$
C^d\bmod n
$$

can involve extremely large intermediate numbers.

Square-and-multiply performs modular exponentiation efficiently using the binary representation of the exponent.

## 18.2 Basic Rule

For each exponent bit:

- Always perform a square operation.
- Perform an additional multiply operation when the bit is 1.

Therefore:

$$
0\rightarrow S
$$

$$
1\rightarrow S+M
$$

where:

- $S$ = Square.
- $M$ = Multiply.

## 18.3 Worked Example

Calculate:

$$
5^8\bmod13
$$

Convert the exponent to binary:

$$
8=1000_2
$$

Initialize:

$$
a=1
$$

Process the bits from left to right.

| Bit | Operation | Calculation | Result |
|---|---|---|---:|
| 1 | Square + Multiply | $(1^2\times5)\bmod13$ | 5 |
| 0 | Square | $5^2\bmod13$ | 12 |
| 0 | Square | $12^2\bmod13$ | 1 |
| 0 | Square | $1^2\bmod13$ | 1 |

Final result:

$$
\boxed{5^8\bmod13=1}
$$

## 18.4 RSA Example From the Slides

The slides use:

$$
p=7,\quad q=19
$$

$$
n=133
$$

$$
e=5,\quad d=65
$$

For message:

$$
M=10
$$

Encryption:

$$
C=10^5\bmod133=117
$$

Decryption:

$$
M=117^{65}\bmod133=10
$$

The private exponent in binary is:

$$
65=1000001_2
$$

Its square-and-multiply operation sequence is:

```text
1 → Square + Multiply
0 → Square
0 → Square
0 → Square
0 → Square
0 → Square
1 → Square + Multiply
```

# 19. SPA Attack on RSA

## 19.1 Where the Leakage Comes From

A naïve RSA implementation executes different operations depending on the private exponent bit.

```python
result = 1

for bit in private_exponent_bits:
    result = (result * result) % n

    if bit == 1:
        result = (result * ciphertext) % n
```

When a bit is zero:

```text
Square
```

When a bit is one:

```text
Square + Multiply
```

If the operations create distinguishable power patterns, the attacker may recognize them in a measured trace.

## 19.2 Recovering Key Bits

Suppose a trace contains the following operation pattern:

```text
SM | S | SM | SM | S | SM | SM | S
```

Interpret:

```text
SM → 1
S  → 0
```

Recovered bits:

$$
10110110_2
$$

In hexadecimal:

$$
\boxed{0xB6}
$$

This corresponds to the key-recovery exercise in the slides.

## 19.3 Identifying Squares and Multiplies

The lecturer emphasized an important observation:

**Square operations always occur, but multiply operations are conditional.**

Therefore:
- Two square operations can occur consecutively.
- Two conditional multiply operations cannot occur consecutively in the basic algorithm.

Possible patterns for two bits:

| Bits | Operations |
|---|---|
| 00 | S S |
| 01 | S S M |
| 10 | S M S |
| 11 | S M S M |

This structural information helps identify operations even if their power amplitudes are not obviously different.

## 19.4 Countermeasure: Square-and-Multiply-Always

A simple defense is to execute both types of operations regardless of the secret bit.

Conceptually:

```text
For every exponent bit:

    Compute square result.
    Compute multiply candidate.
    Select the mathematically correct result.
```

This makes the visible operation sequence more uniform.

However, result selection and other implementation details must also avoid introducing secret-dependent leakage.

> [!important]
> SPA exploits key-dependent operation patterns. A defense must prevent those patterns from revealing the secret.

## 19.5 ECC Analogy

ECC implementations may use double-and-add algorithms.

The equivalent pattern is:

$$
0\rightarrow D
$$

$$
1\rightarrow D+A
$$

where:
- $D$ = Point doubling.
- $A$ = Point addition.

If these operations are distinguishable, secret scalar bits may leak through a similar mechanism.

# 20. AES and Statistical Side-Channel Attacks

RSA SPA can reveal bits directly because its execution pattern may depend visibly on the secret exponent.

AES attacks often require a statistical approach.

## 20.1 AES Overview

AES is a symmetric block cipher.

| Property | AES |
|---|---|
| Block size | 128 bits |
| Key sizes | 128, 192, 256 bits |
| State | $4\times4$ bytes |
| AES-128 rounds | 10 |

The important round operations are:

1. SubBytes.
2. ShiftRows.
3. MixColumns.
4. AddRoundKey.

The final round omits MixColumns.

## 20.2 Why Statistical Analysis Is Needed

A single AES trace may not directly reveal the key.

Instead, an attacker collects many power or EM measurements while the device encrypts different known plaintexts using the same key.

For every plaintext:

$$
P_i
$$

the attacker obtains a trace:

$$
L_i
$$

The attacker looks for a statistical relationship between the measured traces and hypothetical key-dependent intermediate values.

---

# 21. Gray-Box Attack Model

Side-channel analysis commonly uses a **gray-box** attack model.

The attacker may know:

- The cryptographic algorithm.
- The plaintext and ciphertext.
- Some implementation details.
- The hardware platform.

However, the secret key remains unknown.

The attacker does not necessarily need the implementation's complete source code or internal design.

---

# 22. Divide-and-Conquer Against AES

## 22.1 Problem With Brute Force

AES-128 uses a 128-bit secret key.

The complete key space contains:

$$
2^{128}
$$

possibilities.

Brute-forcing this space is computationally infeasible.

## 22.2 Attack One Byte at a Time

AES uses a 16-byte state and a 16-byte key for AES-128.

Instead of attacking the entire key, target each byte independently.

Each byte contains eight bits.

Therefore, the number of hypotheses per byte is:

$$
2^8=256
$$

Repeat the attack for all 16 key bytes.

Total number of individual byte hypotheses tested:

$$
16\times256=4096
$$

This is dramatically smaller than testing every possible complete AES-128 key.

> [!important]
> This reduction works because the attack identifies independently exploitable intermediate computations involving individual key bytes.
>
> It is not a general mathematical reduction of AES brute-force complexity.

# 23. Trace Acquisition for CPA

The attacker queries the encryption device using multiple known plaintexts.

For example:

$$
P_1,P_2,\ldots,P_n
$$

The device generates ciphertexts:

$$
C_1,C_2,\ldots,C_n
$$

For each execution, the attacker records a power trace:

$$
L_1,L_2,\ldots,L_n
$$

The collected dataset is:

$$
\{(P_i,C_i,L_i)\}_{i=1}^{n}
$$

The secret key remains constant across the measurements.

## 23.1 Trace Alignment

A typical statistical attack assumes corresponding operations occur at approximately the same positions across traces.

For example:

```text
Trace 1: ----SBox0----SBox1----SBox2----
Trace 2: ----SBox0----SBox1----SBox2----
Trace 3: ----SBox0----SBox1----SBox2----
```

This enables the attacker to compare measurements corresponding to the same operation.

Desynchronization can make statistical analysis more difficult.

# 24. Choosing the Target Intermediate Value

The attacker needs to identify an intermediate computation that depends on:

1. Known plaintext.
2. Unknown key material.

The lecture uses the output of the first-round AES S-box.

For plaintext byte $P_i$ and key-byte hypothesis $k$:

$$
\boxed{V_i(k)=SBox(P_i\oplus k)}
$$

The attacker knows $P_i$.

The attacker guesses $k$.

Therefore, the intermediate value can be calculated for every possible key hypothesis.

Possible guesses:

$$
k\in\{0,1,\ldots,255\}
$$

# 25. Leakage Models

## 25.1 Why We Need a Leakage Model

The oscilloscope measures electrical signals.

It does not directly reveal numerical intermediate values or secret keys.

The attacker needs a mathematical relationship between the hypothetical intermediate value and its expected physical leakage.

This relationship is called a **leakage model**.

```text
Key hypothesis
      |
      v
Calculate intermediate value
      |
      v
Apply leakage model
      |
      v
Predicted physical leakage
      |
      v
Compare with measured traces
```

Common models:
- Hamming Weight.
- Hamming Distance.
- Identity.
- Mono-bit.

The lecture focuses mainly on Hamming Weight and Hamming Distance.

---

# 26. Hamming Weight (HW)

## 26.1 Definition

Hamming Weight is the number of bits equal to 1 in a binary value.

$$
\boxed{HW(x)=\text{Number of 1 bits in }x}
$$

Example:

$$
x=10110100_2
$$

Count the ones:

$$
HW(x)=4
$$

Another example:

$$
HW(00101111_2)=5
$$

## 26.2 Why HW Models Power Leakage

Consider a data bus that is precharged to zero before transferring a new value.

Initial state:

```text
00000000
```

New value:

```text
10110100
```

Four bits must transition from zero to one.

The associated switching activity may be approximately related to the Hamming Weight of the new value.

This is why Hamming Weight is a commonly used leakage model for certain microcontroller implementations.

---

# 27. Hamming Distance (HD)

## 27.1 Definition

Hamming Distance counts how many corresponding bits differ between two binary values.

$$
\boxed{HD(x,y)=HW(x\oplus y)}
$$

## 27.2 Example

Initial value:

```text
1011
```

New value:

```text
0010
```

Perform XOR:

```text
1011
0010
----
1001
```

Two bits differ.

Therefore:

$$
HD(1011,0010)=2
$$

## 27.3 Another Example

Initial value:

```text
1011
```

New value:

```text
0100
```

XOR:

```text
1011
0100
----
1111
```

All four bits change.

Therefore:

$$
HD(1011,0100)=4
$$

## 27.4 Why HD Models Power Leakage

Registers and flip-flops store binary values.

When an existing value is overwritten, switching activity depends on how many bits change.

Therefore:

$$
P\propto HD(x_{\text{old}},x_{\text{new}})
$$

This is why Hamming Distance is often useful when modeling hardware implementations and register transitions.

## 27.5 Relationship Between HW and HD

If the old value is zero:

$$
HD(0,x)=HW(x)
$$

Therefore, Hamming Weight can be understood as a special case of Hamming Distance when the initial state is zero.

## 27.6 HW vs HD

| Hamming Weight | Hamming Distance |
|---|---|
| Counts the number of ones | Counts the number of changed bits |
| Operates on one value | Operates on two values |
| Useful for precharged-bus models | Useful for register-transition models |
| $HW(x)$ | $HW(x\oplus y)$ |

> [!tip] Remember
> HW asks: **How many ones are there?**
>
> HD asks: **How many bits changed?**

# 28. Correlation Power Analysis (CPA)

CPA is the central statistical attack discussed in this lecture.

## 28.1 Main Idea

The attacker has:

1. Actual measured traces.
2. Known plaintexts.
3. A set of possible key-byte guesses.
4. A leakage model.

For each key hypothesis, the attacker calculates the expected leakage.

The attacker then determines which predicted leakage vector is most strongly correlated with the real measurements.

The correct key hypothesis is expected to produce a stronger statistical relationship than incorrect hypotheses when the leakage model and measurements are suitable.

---

# 29. Pearson Correlation

CPA commonly uses Pearson correlation.

$$
\boxed{
\rho(X,Y)=
\frac{\operatorname{Cov}(X,Y)}
{\sigma_X\sigma_Y}
}
$$

Where:

- $\operatorname{Cov}(X,Y)$ is the covariance.
- $\sigma_X$ is the standard deviation of $X$.
- $\sigma_Y$ is the standard deviation of $Y$.

Possible correlation values:

$$
-1\leq\rho\leq1
$$

Interpretation:

| Correlation | Meaning |
|---|---|
| Near +1 | Strong positive linear relationship |
| Near -1 | Strong negative linear relationship |
| Near 0 | Little or no linear relationship |

For CPA, both positive and negative correlation can reveal a secret-dependent relationship.

Therefore, the attacker commonly examines:

$$
|\rho(X,Y)|
$$

The goal is to identify the hypothesis with the strongest absolute correlation.

---

# 30. Complete CPA Attack on One AES Byte

Assume:
- We know $n$ plaintexts.
- We recorded $n$ corresponding power traces.
- The AES key byte is unknown.

## Step 1: Generate Key Hypotheses

Test all 256 possible key-byte values:

$$
k=0,1,\ldots,255
$$

## Step 2: Calculate Intermediate Values

For every plaintext and each key guess:

$$
V_i(k)=SBox(P_i\oplus k)
$$

## Step 3: Apply the Leakage Model

For the Hamming Weight model:

$$
H_i(k)=HW(V_i(k))
$$

Therefore:

$$
\boxed{
H_i(k)=HW(SBox(P_i\oplus k))
}
$$

This predicts the leakage for plaintext $P_i$ under key hypothesis $k$.

## Step 4: Compare Predictions With Measurements

At a particular time position $t$, the attacker has measured values:

$$
L_1(t),L_2(t),\ldots,L_n(t)
$$

For one key hypothesis, predicted values are:

$$
H_1(k),H_2(k),\ldots,H_n(k)
$$

Calculate:

$$
r_k(t)=
\rho(
\{H_i(k)\}_{i=1}^{n},
\{L_i(t)\}_{i=1}^{n}
)
$$

## Step 5: Identify the Key

Find the key hypothesis that gives the strongest absolute correlation:

$$
\boxed{
k^*=\arg\max_k\max_t |r_k(t)|
}
$$

Here, $k^*$ is the attacker's selected key-byte candidate.

## Step 6: Repeat for All Key Bytes

Repeat the same procedure for the other 15 bytes.

Combine the recovered bytes:

$$
K=K_0\|K_1\|\cdots\|K_{15}
$$

This reconstructs the AES-128 key if all 16 bytes are recovered correctly.

# 32. Why Attack the First or Last AES Round?

The lecturer explains that attackers commonly target either the first or last round.

## 32.1 First Round

The first-round S-box output is:

$$
SBox(P_i\oplus K_i)
$$

It depends directly on:
- One known plaintext byte.
- One unknown key byte.

The attacker only needs:

$$
2^8=256
$$

hypotheses.

## 32.2 Middle Rounds

As AES progresses, operations such as MixColumns spread information across multiple bytes.

Intermediate values begin depending on several key bytes.

Therefore, attacks against deeper rounds can require substantially more complex key hypotheses.

The lecturer illustrates how the number of hypothesized secret bits can increase from 8 to approximately 40 in a deeper-round example:

$$
2^8\rightarrow2^{40}
$$

## 32.3 Last Round

An attacker can also use known ciphertext and relationships involving the final-round transformations.

Therefore:

$$
\boxed{
\text{First-round attacks use plaintext}
}
$$

$$
\boxed{
\text{Last-round attacks use ciphertext}
}
$$

For AES-128, the key schedule allows the original key to be reconstructed from a complete round key.

# 33. Side-Channel Attack Evaluation Metrics

The lecture introduces three important concepts:

1. Minimum Traces to Disclosure.
2. Guessing Entropy.
3. Success Rate.

These metrics describe attack performance.

---

# 34. Minimum Traces to Disclosure (MTD)

## Definition

MTD describes the minimum number of measurements required for the attack to distinguish the correct key under the chosen evaluation conditions.

Because CPA is a statistical attack, more traces generally provide stronger evidence.

Example:

| Traces | Result |
|---:|---|
| 50 | Correct key not distinguishable |
| 100 | Several competing hypotheses |
| 200 | Correct key begins to separate |
| 500 | Correct key clearly distinguished |

In this illustrative example, the required number of traces is somewhere around the point at which the correct key becomes reliably distinguishable.

The exact threshold depends on the evaluation procedure.

> [!tip]
> Fewer required traces generally mean a more efficient attack against the evaluated implementation.

---

# 35. Guessing Entropy (GE)

## 35.1 Definition

Guessing Entropy measures the average rank of the correct key hypothesis across repeated attacks.

Key candidates are ordered by their correlation scores or other attack scores.

In the lecture's convention, ranks start at zero.

Therefore:

$$
\boxed{GE=0}
$$

means the correct key is ranked first on average.

## 35.2 Example

Suppose the true key byte is:

```text
0x3A
```

After CPA, the candidates are ranked:

| Rank | Candidate | Correct? |
|---:|---|---|
| 0 | 0x91 | No |
| 1 | 0x12 | No |
| 2 | 0x3A | Yes |
| 3 | 0x56 | No |

The correct key has rank:

$$
2
$$

There are two candidates ahead of it.

If another attack produces:

| Rank | Candidate | Correct? |
|---:|---|---|
| 0 | 0x3A | Yes |
| 1 | 0x91 | No |
| 2 | 0x12 | No |

the correct key now has rank:

$$
0
$$

## 35.3 Why GE Is Averaged

An individual attack may produce different results because of noise and sampling variation.

Therefore, researchers repeat attacks and calculate the average rank of the correct key.

Conceptually:

$$
GE(N)=
\frac{1}{R}
\sum_{j=1}^{R}
\operatorname{rank}_j(K)
$$

Where:
- $N$ = number of traces per attack.
- $R$ = number of repeated attacks.
- $K$ = correct key.

## 35.4 Understanding the GE Graph

A successful attack usually produces a curve that decreases toward zero as more traces are collected.

```text
Guessing Entropy
      |
High  |\
      | \
      |  \
      |   \______
    0 |___________
      |
      +----------------
         Number of traces
```

> [!important]
> In the lecture's zero-based rank convention:
>
> $GE=0$ means the correct key is ranked first.
>
> A lower GE indicates fewer competing candidates ahead of the correct key.

---

# 36. Success Rate (SR)

## Definition

Success Rate estimates how frequently the attack successfully recovers the correct key.

For a fixed number of traces:

$$
\boxed{
SR=
\frac{\text{Number of successful attacks}}
{\text{Total number of repeated attacks}}
}
$$

Example:

Suppose 100 independent attacks are performed.

If 85 correctly recover the key:

$$
SR=\frac{85}{100}=0.85
$$

Therefore:

$$
SR=85\%
$$

If every attack succeeds:

$$
\boxed{SR=1}
$$

For a successful attack, the SR curve generally increases as more traces become available.

## GE vs SR

| Guessing Entropy | Success Rate |
|---|---|
| Average rank of correct key | Frequency of successful recovery |
| Lower is better for attacker | Higher is better for attacker |
| Ideal value: 0 | Ideal value: 1 |
| Indicates remaining guessing effort | Indicates recovery reliability |

---

# 37. Side-Channel Countermeasures

The last major topic covered in the live lecture is protection against side-channel attacks.

## 37.1 Fundamental Problem

Side-channel leakage is related to the physical operation of electronic devices.

Computation requires physical activity.

Therefore, completely eliminating every physical effect is extremely difficult.

Instead, countermeasures aim to weaken or remove the useful relationship between sensitive data and measured leakage.

## 37.2 Three Main Strategies

The lecturer identifies three general objectives:

1. Suppress leakage.
2. Hide leakage.
3. Transform leakage.

The main categories are **hiding** and **masking**.

Hiding:
- Reduce useful signal.
- Increase noise.
- Make physical activity less distinguishable.

Masking:
- Randomize sensitive intermediate values.
- Transform the relationship between sensitive data and leakage.

Countermeasures can operate at several levels:
- Transistor level.
- Gate/circuit level.
- Algorithm level.
- Software level.
- Protocol level.

---

# 38. Hiding

Hiding attempts to make secret-dependent leakage less useful to an attacker.

There are two main approaches.

## 38.1 Signal Reduction

Reduce the amount of useful leakage.

Possible techniques:
- Balanced hardware.
- Complementary computations.
- Electromagnetic shielding.
- Power isolation.

## 38.2 Noise Introduction

Introduce unrelated activity or variation that makes the secret-dependent signal harder to extract.

Possible techniques:
- Dummy operations.
- Parallel computation.
- Random noise generators.
- Shuffling.
- Jitter.
- Desynchronization.

Conceptually:

$$
L_{\text{measured}}
=
L_{\text{secret}}
+
L_{\text{noise}}
$$

Increasing noise makes statistical key recovery more difficult when the useful leakage is not correspondingly strengthened.

---

# 39. Balancing and Complementary Computation

Balancing attempts to make physical activity approximately independent of the sensitive value.

Suppose the device normally computes:

$$
y=f(x)
$$

A balancing circuit performs additional complementary computation.

The goal is to obtain:

$$
P_{\text{total}}(x)
\approx
\text{constant}
$$

regardless of $x$.

## 39.1 Dual-Rail Encoding

The slides introduce an example in which values are represented using complementary encodings:

$$
0\rightarrow01
$$

$$
1\rightarrow10
$$

Using complementary circuits and suitable precharge phases can make switching activity more uniform.

## 39.2 Limitations

Balancing increases implementation cost.

It may require:
- Additional logic.
- Additional registers.
- More power.
- More silicon area.

Real circuits can also exhibit mismatches and process variations.

A sufficiently localized measurement may still detect differences between supposedly balanced operations.

Therefore, balancing reduces leakage but does not automatically guarantee complete protection.

---

# 40. Shuffling and Desynchronization

Statistical attacks often assume corresponding sensitive operations occur at the same positions across traces.

For example:

```text
Trace 1: K0 K1 K2 K3
Trace 2: K0 K1 K2 K3
Trace 3: K0 K1 K2 K3
```

A defender can randomize the order of independent operations.

For example:

```text
Trace 1: K0 K1 K2 K3
Trace 2: K2 K0 K3 K1
Trace 3: K1 K3 K0 K2
```

Now the operation involving a particular key byte does not always appear at the same time.

## 40.1 AES Example

The lecturer uses the independent first-round AES S-box computations as an example.

Instead of evaluating:

```text
SBox0 → SBox1 → SBox2 → ... → SBox15
```

the implementation can change their execution order.

This creates trace misalignment.

## 40.2 Why It Helps

Ordinary CPA becomes more difficult when the same operation does not align across measurements.

However, an attacker may perform additional preprocessing, alignment, or more advanced statistical analysis.

Therefore, shuffling increases attack difficulty rather than necessarily eliminating the leakage.

---

# 41. Masking: Introduction

The live lecture introduces masking but defers its detailed explanation.

Masking transforms sensitive computation by introducing randomness.

Instead of directly processing:

$$
x
$$

the implementation may process a randomized representation:

$$
x'=x\oplus r
$$

where $r$ is a fresh random mask.

The computation must be modified so that the final result remains mathematically correct.

The objective is to make direct leakage depend on randomized intermediate values rather than the original sensitive value.

Conceptually:

```text
Sensitive value x
       |
       v
Generate random mask r
       |
       v
Calculate x XOR r
       |
       v
Masked computation
       |
       v
Mask correction
       |
       v
Correct output
```

The output remains functionally correct, while internal representations change across executions.

> [!important]
> Hiding mainly reduces the usefulness of measured leakage.
>
> Masking changes the internal representation of sensitive information so direct leakage no longer has the same simple relationship with the secret.

---

# 42. Countermeasure Trade-Offs

Side-channel protections introduce additional costs.

Possible overheads include:
- More computation.
- Additional silicon area.
- Higher energy consumption.
- Greater implementation complexity.
- Random-number generation requirements.

A device designer must balance security requirements against implementation constraints.

The lecturer emphasized the economic perspective.

A countermeasure does not always need to eliminate every possible attack.

It may instead increase the required equipment, number of traces, analysis effort, and attack cost sufficiently to make exploitation impractical for the intended use case.

# 43. Slide-Deck Continuation: Advanced Masking

> [!note]
> The following material appears in the later slides. The lecturer stated that detailed masking would continue in the next class.

## 43.1 Boolean Masking

Boolean masking represents sensitive data using multiple shares.

For example:

$$
x=x_0\oplus x_1
$$

Neither individual share needs to reveal the sensitive value when the shares are correctly generated.

## 43.2 Higher-Order Masking

For a $d$-order Boolean masking scheme, the sensitive value is represented using:

$$
d+1
$$

shares.

$$
x=x_0\oplus x_1\oplus\cdots\oplus x_d
$$

In the ideal probing-security model, observing up to $d$ shares should not reveal information about the secret.

However, practical implementations require careful handling of the shares.

## 43.3 Challenges

The slides identify several issues:

- High-quality randomness is required.
- Attackers may combine information from multiple shares.
- Higher-order attacks may remain possible.
- Hardware glitches can unintentionally combine shares.
- Compiler and pipeline behavior may weaken isolation.
- Masking nonlinear operations such as S-boxes is more complex than masking linear operations.

> [!note]
> Profiled attacks were introduced during Lecture 3 but their detailed discussion was deferred.

## 44.1 Two Phases

### Profiling Phase

The attacker uses a device with known or controllable secrets.

The attacker collects labeled traces and constructs a statistical or machine-learning model.

```text
Known-key device
       |
       v
Collect labeled traces
       |
       v
Train model
```

### Attack Phase

The attacker collects measurements from a target device with an unknown secret.

```text
Unknown-key device
       |
       v
Collect attack traces
       |
       v
Apply trained model
       |
       v
Infer secret key
```

## 44.2 Template Attacks

Template attacks construct statistical leakage models using measurements obtained from a profiling device.

The slides describe Gaussian templates using estimated means and variances for different key classes.

During the attack, measurements from the target are compared with the templates.

The attacker selects the most likely key hypothesis.

## 44.3 Machine Learning

Profiled attacks can use supervised machine-learning methods such as:

- Support Vector Machines.
- Random Forest.
- Multilayer Perceptrons.
- Convolutional Neural Networks.

A model is trained to associate measured traces with secret-dependent labels.

## 44.4 Portability

Portability refers to how well a model trained on one device works against another device.

Challenges include:
- Manufacturing variations.
- Environmental differences.
- Measurement setup differences.
- EM probe placement.
- Different noise characteristics.

The slides illustrate that models trained on one device may perform poorly on another.

## 44.5 Overfitting

A model may learn device-specific characteristics rather than generalizable secret-dependent leakage.

This creates overfitting.

One approach discussed in the slides is using multiple devices for model training.

This aims to improve portability to unseen devices.
