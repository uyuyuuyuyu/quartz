# 1. Recap: Cyber-Physical Systems

A **Cyber-Physical System (CPS)** tightly integrates:

- **Physical components**
  - sensors
  - actuators
  - physical processes
- **Cyber components**
  - computation
  - communication
  - control

## CPS Architecture

### Perception Layer

Interacts with the physical world.

Examples:

- sensors
- RFID
- actuators
- cameras

### Transmission Layer

Connects the physical and cyber components.

Examples:

- Wi-Fi
- Bluetooth
- gateways
- Internet

### Application Layer

Processes information and provides services.

Examples:

- data analysis
- monitoring systems
- control systems
- user applications

## Why CPS Security is Different

Traditional cybersecurity mainly protects digital systems.

CPS security must consider both:

```text
Cyber world <------> Physical world
```

An attacker may:

- use a cyberattack to cause a physical effect
- use physical access to compromise cyber security

Therefore CPS security requires a **holistic, multi-layered approach**.

> [!important]
> The goal is not necessarily perfect security.
>
> The system should be secure enough that the cost/effort of attacking it is greater than the attacker's benefit.

---

# 2. CIA Triad

The three fundamental security goals are:

## Confidentiality

> Prevent unauthorized access to information.

Examples:

- passwords should not be readable while transmitted
- private files should not be accessible without authorization

Confidentiality applies to both:

```text
Data at rest
+
Data in transit
```

---

## Integrity

> Prevent unauthorized modification of information.

Example:

```text
Authorized transaction:
$10

Attacker changes it to:
$100
```

Integrity mechanisms should:

- prevent unauthorized modification
- detect modification

---

## Availability

> Information and services should be available to authorized users when needed.

Security mechanisms should not introduce so much overhead that the service becomes unusable.

---

# 3. Extended Security Properties

In addition to the CIA triad:

| Property | Meaning |
|---|---|
| Confidentiality | Prevent unauthorized disclosure |
| Integrity | Prevent unauthorized modification |
| Availability | Ensure timely access |
| Authenticity | Verify identity/origin |
| Non-repudiation | Sender cannot later deny an action |
| Privacy | Control how personal information is accessed and used |

## Confidentiality vs Privacy

These are related but not identical.

### Confidentiality

Focuses on:

> "Who is allowed to access the data?"

### Privacy

More broadly focuses on:

> "How is my data accessed, shared and used?"

Example:

You may allow family to view your photos but not allow a company to use those photos for AI training.

That is a **privacy** decision.

Confidentiality would mean preventing unauthorized people from viewing the photos at all.

# 5. Kerckhoffs's Principle

A secure cryptosystem should remain secure even if the attacker knows the algorithm.

Therefore:

```text
Algorithm = PUBLIC
Key       = SECRET
```

Modern algorithms such as AES and RSA are publicly documented.

The attacker's main objective is often:

> **Recover the secret key.**

# 6. Symmetric-Key Cryptography

Symmetric encryption uses the **same secret key** for encryption and decryption.

```text
Alice                         Bob

Plaintext
   |
Encrypt with K
   |
Ciphertext ------------------>
                              |
                         Decrypt with K
                              |
                          Plaintext
```

Mathematically:

$$
C = E_K(P)
$$

$$
P = D_K(C)
$$

Where:

- $P$ = plaintext
- $C$ = ciphertext
- $K$ = secret key

## Advantage

Very efficient for encrypting large amounts of data.

## Main Problem

Alice and Bob must somehow securely share the secret key.

> [!question]
> How do they securely exchange the symmetric key?
>
> Public-key cryptography is used to solve this problem.

# 7. AES - Advanced Encryption Standard

AES is a **symmetric block cipher**.

## AES Properties

| Property | Value |
|---|---|
| Standardized | 2001 |
| Block size | 128 bits |
| State | 4 × 4 byte matrix |
| Key sizes | 128 / 192 / 256 bits |
| Rounds | 10 / 12 / 14 |

Since:

$$
128 \text{ bits} = 16 \text{ bytes}
$$

AES arranges the input as:

```text
4 × 4 matrix
= 16 bytes
```

This matrix is called the **state**.

---

# 8. AES Round Operations

Each normal AES round contains four transformations.

## 1. SubBytes

Each byte is replaced using a predefined substitution table called an **S-box**.

```text
byte -> S-box -> new byte
```

---

## 2. ShiftRows

Rows are cyclically shifted.

Conceptually:

```text
Row 0 -> shift 0
Row 1 -> shift 1
Row 2 -> shift 2
Row 3 -> shift 3
```

---

## 3. MixColumns

Each column is transformed mathematically.

Purpose:

- mix information
- increase diffusion

---

## 4. AddRoundKey

The current state is XORed with a round key.

$$
S' = S \oplus K_r
$$

---

# 9. AES Round Structure

For AES-128:

```text
Plaintext
   |
Initial AddRoundKey
   |
+----------------------+
| Round 1              |
| SubBytes             |
| ShiftRows            |
| MixColumns           |
| AddRoundKey          |
+----------------------+
          |
        ...
          |
+----------------------+
| Round 9              |
+----------------------+
          |
+----------------------+
| Round 10             |
| SubBytes             |
| ShiftRows            |
| AddRoundKey          |
+----------------------+
          |
      Ciphertext
```

> [!important]
> The final AES round does **not** contain MixColumns.

Number of rounds:

```text
AES-128 -> 10 rounds
AES-192 -> 12 rounds
AES-256 -> 14 rounds
```

---

# 10. Why AES is Important for Side-Channel Attacks

Suppose an intermediate AES operation is:

$$
S = P \oplus K
$$

Where:

- $P$ = known plaintext
- $K$ = secret key
- $S$ = intermediate value

If an attacker somehow learns $S$:

$$
K = P \oplus S
$$

Therefore the attacker does not necessarily need to mathematically break AES.

Instead, they can try to learn information about:

> **AES intermediate states**

through physical leakage.

## Why First and Last Rounds?

The lecturer emphasized that side-channel attacks often target:

- the first AES round
- the last AES round

because intermediate values there have relatively direct relationships with:

- known plaintext
- known ciphertext
- secret key

Later-round internal states are harder to relate directly to the key.

---

# 11. AES Key Schedule

AES begins with a **master key**.

Round keys are derived deterministically:

```text
Master Key
    |
Key Schedule
    |
Round Key 0
Round Key 1
Round Key 2
...
Round Key N
```

Because the transformation is deterministic:

> Recovering a complete round key can allow reconstruction of the master key.

Therefore recovering the first or last round key can defeat the entire encryption.

---

# 12. AES Modes of Operation

AES only processes a **128-bit block**.

For larger files, a mode of operation determines how blocks are processed.

Main modes discussed:

- ECB
- CBC
- CTR
- CFB
- OFB

---

## ECB - Electronic Codebook

Each block is encrypted independently.

```text
P1 -> AES -> C1
P2 -> AES -> C2
P3 -> AES -> C3
```

Problem:

If:

$$
P_i = P_j
$$

then:

$$
C_i = C_j
$$

Therefore repeated patterns in the plaintext can remain visible.

### Main Idea

> ECB leaks structural patterns.

Useful mainly for very small/single-block data.

---

## CBC - Cipher Block Chaining

Each plaintext block is XORed with the previous ciphertext block.

First block:

$$
C_1 = E_K(P_1 \oplus IV)
$$

Following blocks:

$$
C_i = E_K(P_i \oplus C_{i-1})
$$

```text
IV
 |
 XOR <- P1
 |
AES
 |
C1
 |
 XOR <- P2
 |
AES
 |
C2
```

This chaining prevents repeated plaintext blocks from producing obvious repeated ciphertext patterns.

---

## CTR - Counter Mode

AES encrypts counter values instead of plaintext directly.

```text
Counter
   |
  AES
   |
Keystream
   |
  XOR <- Plaintext
   |
Ciphertext
```

Useful for:

- high-speed systems
- parallel processing

---

## CFB - Cipher Feedback

Previous ciphertext is fed back into the encryption function.

```text
Previous Ciphertext
       |
      AES
       |
      XOR <- Plaintext
       |
   Ciphertext
```

---

## OFB - Output Feedback

Similar to CFB, but feeds back the encryption **output** instead of ciphertext.

Useful in noisy channels because transmission errors do not propagate indefinitely.

Example from lecture:

- satellite communication

# 13. Hash Functions

A hash function maps arbitrary input to a fixed-size digest.

$$
h = H(M)
$$

Think of it as a:

> **digital fingerprint**

## Important Properties

### One-Way

Easy:

$$
M \rightarrow H(M)
$$

Hard:

$$
H(M) \rightarrow M
$$

---

### Avalanche Effect

A tiny input change should produce a very different hash.

```text
Message A
   |
 Hash
   |
abc123...

Change 1 bit

Message B
   |
 Hash
   |
f92d7e...
```

Hashes can therefore help detect modification.

> [!note]
> A plain hash by itself does not prove who created the message, because anyone can compute a hash.

---

# 14. Message Authentication Code (MAC)

A MAC uses:

```text
Message + Secret Key
```

to generate an authentication value.

$$
MAC = F(M,K)
$$

Alice and Bob both know $K$.

```text
Alice

Message + Secret Key
        |
       MAC
        |
Message + MAC
        |
        v
       Bob

Bob recomputes MAC using same key
```

If:

$$
MAC_{received} = MAC_{calculated}
$$

the message is accepted.

---

# 15. Hash vs MAC

| Hash | MAC |
|---|---|
| No secret key | Uses secret key |
| Anyone can calculate | Only key holders can calculate |
| Detects changes relative to trusted digest | Provides keyed authentication |
| Integrity checking | Integrity + shared-key authentication |

Easy way to remember:

```text
Hash = fingerprint

MAC = keyed fingerprint
```

## Why a Plain Hash is Not Authentication

Suppose Alice sends:

```text
Message:
Pay Bob $10

Hash:
H(message)
```

Eve changes the message to:

```text
Pay Bob $1000
```

Because hashing uses no secret key, Eve can calculate:

```text
H(modified message)
```

and replace the old hash.

With a MAC, Eve cannot create a valid new MAC unless she knows the secret key.

---

# 16. Encryption vs Hash vs MAC

| Mechanism | Main Goal |
|---|---|
| Encryption | Confidentiality |
| Hash | Detect modification against trusted digest |
| MAC | Integrity + shared-key authentication |
| Digital Signature | Integrity + origin + non-repudiation |

# 17. Authenticated Encryption

Encryption alone mainly provides:

> Confidentiality

Modern applications usually need:

$$
\text{Confidentiality + Integrity}
$$

This motivates:

## AEAD

**Authenticated Encryption with Associated Data**

Typical structure:

```text
Plaintext
Key
Nonce
Associated Data
       |
      AEAD
     /    \
Ciphertext  Authentication Tag
```

- ciphertext → confidentiality
- tag → integrity/authentication

---

# 18. AES-GCM

AES-GCM is an AEAD construction.

Inputs include:

- plaintext
- key
- nonce
- associated data

Outputs:

- ciphertext
- authentication tag

```text
Inputs
  |
  v
AES-GCM
 /    \
v      v
Ciphertext   Tag
```

During decryption, the receiver verifies the authentication tag.

If verification fails:

```text
Reject data
```

# 19. Ascon

Ascon is introduced as a **nonce-based AEAD** design.

Properties from the lecture:

- 320-bit internal state
- target security: 128 bits
- sponge-based construction
- substitution-permutation network

It performs four main phases:

1. Initialization
2. Associated Data Processing
3. Plaintext Processing
4. Finalization

---

## Ascon Initialization

State initialized using:

- IV
- secret key
- nonce

```text
IV || Key || Nonce
        |
    Permutation
        |
   Internal State
```

---

## Associated Data Processing

Associated data is:

> authenticated but not encrypted

It may contain public information sent alongside ciphertext.

---

## Plaintext Processing

Plaintext blocks are injected into the state and ciphertext blocks are produced.

---

## Finalization

The secret key is injected again and an authentication tag is produced.

---

# 20. Rate and Capacity in Ascon

Ascon's 320-bit state is divided into:

$$
r + c = 320
$$

Where:

- $r$ = rate
- $c$ = capacity

### Rate

Controls how much data is processed per iteration.

Higher rate:

```text
More data per iteration
-> higher throughput
```

### Capacity

Internal portion not directly exposed.

Lecture framing:

```text
Lower rate
-> larger capacity
-> larger security margin
-> lower performance
```

---

## Ascon-128 vs Ascon-128a

| | Ascon-128 | Ascon-128a |
|---|---:|---:|
| State | 320 bits | 320 bits |
| Security | 128 bits | 128 bits |
| Rate | 64 bits | 128 bits |
| Capacity | 256 bits | 192 bits |
| Tag | 128 bits | 128 bits |
| $p^a$ | 12 rounds | 12 rounds |
| $p^b$ | 6 rounds | 8 rounds |

Lecture conclusion:

> Ascon-128a can achieve higher throughput because it processes twice as much data per block.

# 21. Asymmetric / Public-Key Cryptography

The main problem with symmetric encryption is:

> How do Alice and Bob securely share the secret key?

Public-key cryptography uses **two mathematically related keys**.

```text
Public Key
- shared with everyone

Private Key
- kept secret by owner
```

---

# 22. Public Key vs Private Key

Bob creates a key pair:

```text
Bob
 |
 +---- Public Key
 |       -> share with Alice
 |       -> can be public
 |
 +---- Private Key
         -> Bob keeps secret
```

For public-key encryption:

```text
Alice
  |
Message
  |
Encrypt using Bob's PUBLIC key
  |
Ciphertext
  |
  v
Bob
  |
Decrypt using Bob's PRIVATE key
  |
Message
```

> [!important]
> The public and private keys are **different but mathematically related values**.

The public key is designed so that knowing it does not make it practical to derive the private key under the security assumptions of the scheme.

---

# 23. How Symmetric and Asymmetric Encryption Work Together

Public-key cryptography is computationally more intensive.

Symmetric encryption such as AES is much faster for large amounts of data.

So practical systems often do:

```text
Public-key cryptography
        |
Establish a shared secret key
        |
        v
Symmetric encryption
        |
Encrypt large amounts of data
```

Therefore:

$$
\boxed{
\text{Asymmetric crypto establishes key}
\rightarrow
\text{Symmetric crypto encrypts data}
}
$$

Example:

1. Bob creates a public/private key pair.
2. Bob shares his public key.
3. Alice establishes/transports a symmetric session key using Bob's public-key mechanism.
4. Bob uses his private key to obtain the session key.
5. Alice and Bob now use the same symmetric key for AES.

# 24. Diffie-Hellman Key Exchange

Diffie-Hellman allows Alice and Bob to establish a shared secret without directly transmitting that secret.

Public values:

$$
g,n
$$

Alice chooses secret:

$$
x
$$

and computes:

$$
X = g^x \mod n
$$

Bob chooses secret:

$$
y
$$

and computes:

$$
Y = g^y \mod n
$$

They exchange:

```text
Alice ---- X ----> Bob
Alice <--- Y ----- Bob
```

Alice computes:

$$
K = Y^x \mod n
$$

Bob computes:

$$
K = X^y \mod n
$$

Both obtain:

$$
\boxed{K = g^{xy} \mod n}
$$

### Important

Diffie-Hellman is used for:

> **key establishment**

Not directly for:

- message encryption
- digital signing

# 25. RSA

RSA is a public-key cryptographic system.

Security is based on the difficulty of factoring:

$$
n = pq
$$

where $p$ and $q$ are large prime numbers.

## Key Generation

Choose:

$$
p,q
$$

Compute:

$$
n=pq
$$

Choose public exponent:

$$
e
$$

Calculate private exponent:

$$
d
$$

Public key:

$$
(n,e)
$$

Private key:

$$
d
$$

---

## RSA Encryption

$$
C=M^e \mod n
$$

Alice uses Bob's public key.

---

## RSA Decryption

$$
M=C^d \mod n
$$

Bob uses his private key.

---

# 26. RSA Toy Example

Given:

$$
p=7
$$

$$
q=19
$$

Then:

$$
n=pq=133
$$

Choose:

$$
e=5
$$

$$
d=65
$$

Public key:

$$
(133,5)
$$

Private key:

$$
65
$$

Message:

$$
M=10
$$

Encryption:

$$
C=10^5 \mod 133=117
$$

Decryption:

$$
117^{65}\mod133=10
$$

---

# 27. RSA Hard Problem

RSA is secure because:

```text
p, q
 |
 multiply
 |
 n
```

is easy.

But:

```text
n
 |
 factor
 |
p, q
```

is difficult for sufficiently large primes using known classical methods.

If an attacker can recover $p$ and $q$, they can derive the private key.

# 28. Digital Signatures

Digital signatures use public-key cryptography for:

- integrity
- authenticity/origin
- non-repudiation

## Signing

Alice computes:

$$
h=H(M)
$$

Then signs using her **private key**.

```text
Message
  |
 Hash
  |
Digest
  |
Sign using Alice's private key
  |
Signature
```

Alice sends:

```text
Message + Signature
```

---

## Verification

Bob:

1. hashes the received message
2. verifies the signature using Alice's public key
3. checks whether verification succeeds

```text
Received Message -> Hash ------+
                               |
                               | verify
                               |
Signature -> Alice public key -+
```

If valid:

- message has not been modified
- signature corresponds to Alice's key pair

---

# 29. MAC vs Digital Signature

| MAC | Digital Signature |
|---|---|
| Uses shared secret key | Uses public/private key pair |
| Both parties know same secret | Only signer knows private key |
| Only key holders verify | Anyone with public key can verify |
| Integrity + shared-key authentication | Integrity + origin + non-repudiation |

Easy way to remember:

```text
MAC:
Create -> shared secret key
Verify -> shared secret key

Digital signature:
Sign   -> private key
Verify -> public key
```

# 31. Quantum Threat

Modern public-key cryptography relies on mathematical hard problems.

| Cryptosystem | Hard Problem |
|---|---|
| RSA | Prime factorization |
| ECC | Discrete logarithm |

For classical computers these problems are considered difficult at appropriate parameter sizes.

A sufficiently powerful quantum computer could use algorithms such as **Shor's algorithm** to solve these problems much more efficiently.

Therefore quantum computing threatens:

- RSA
- ECC
- Diffie-Hellman-type systems based on discrete logarithms

# 32. Physical vs Logical Qubits

The lecture distinguishes:

## Physical Qubit

Actual hardware qubit.

Physical qubits are noisy and unstable.

## Logical Qubit

Error-corrected qubit constructed from physical qubits.

```text
Many physical qubits
        |
 Error correction
        |
 Logical qubit
```

For cryptographic attacks, the important question is:

> How many useful logical qubits can be created?

# 33. Store Now, Decrypt Later

Also called **SNDL**.

Attack strategy:

```text
Capture encrypted data today
        |
Store it
        |
Wait for stronger quantum computer
        |
Decrypt later
```

This matters for data that must remain confidential for:

- 10 years
- 20 years
- 30+ years

Therefore migration may be necessary **before** a cryptographically relevant quantum computer exists.

# 34. Post-Quantum Cryptography

**Post-Quantum Cryptography (PQC)** is cryptography designed to remain secure against attackers with large-scale quantum computers.

> [!important]
> PQC itself runs on ordinary classical computers.

It does **not** require the user to own a quantum computer.

PQC uses different mathematical hard problems from those used by RSA and ECC.

---

# 35. QKD vs PQC

| Feature | QKD | PQC |
|---|---|---|
| Full name | Quantum Key Distribution | Post-Quantum Cryptography |
| Main use | Key exchange | Key exchange, encryption, signatures |
| Hardware | Specialized quantum hardware | Existing classical devices |
| Main objective in lecture | Confidentiality | Confidentiality, integrity, authenticity, non-repudiation |
| Deployment | New infrastructure | Can replace existing public-key schemes |

## QKD

Uses quantum communication.

Main idea:

> Eavesdropping affects the quantum channel and can therefore be detected.

However, it requires specialized hardware.

## PQC

Designed as a more direct replacement for existing public-key cryptography.

# 41. Side-Channel Analysis

A **Side-Channel Attack (SCA)** exploits information unintentionally leaked by a physical implementation.

Possible side channels:

- timing
- power consumption
- electromagnetic radiation
- acoustic leakage
- motion/sensor data

```text
Cryptographic Computation
          |
          v
 Physical Leakage
 /      |       \
Power  Timing    EM
          |
          v
   Measurements
          |
          v
 Statistical Analysis
          |
          v
Information about secret data
```

---

# 42. Side-Channel Attack vs Cryptanalysis

Traditional cryptanalysis asks:

> "Is there a mathematical weakness in AES?"

Side-channel analysis asks:

> "What does the device reveal while executing AES?"

Therefore:

> [!important]
> Side-channel attacks attack the **implementation**, not necessarily the underlying algorithm.

AES can remain mathematically secure while a specific AES implementation leaks its key.

---

# 43. Non-Invasive Attacks

Many side-channel attacks are **non-invasive**.

The attacker does not need to:

- open the chip
- destroy the device
- physically modify the circuitry

Instead they simply observe physical behavior.

Examples:

```text
Measure execution time
Measure electrical power
Measure EM radiation
Listen to acoustic signals
Read motion sensors
```

# 45. Smartphone Experiment

The lecture reports that, in the research example:

- accelerometer alone gave roughly 67% PIN recovery
- accelerometer + gyroscope gave close to 80%
- attacker was limited to 20 guesses

For a 4-digit PIN:

$$
10^4 = 10,000
$$

possible combinations.

Random one-shot success:

$$
\frac{1}{10000}=0.01\%
$$

Physical leakage dramatically reduces the attacker's uncertainty.

# 47. Why the Smartphone Attack Works

The fundamental problem is not necessarily:

- the PIN algorithm
- the phone model
- the encryption algorithm

The deeper issue is:

> **Physics leaks information.**

If the phone moves:

```text
movement -> sensor measurement
```

That physical leakage cannot be completely eliminated simply by making the PIN longer.

Possible mitigation discussed:

- randomized keypad positions

Example:

```text
Normal keypad:

1 2 3
4 5 6
7 8 9
  0

Randomized:

7 1 5
3 9 0
4 2 8
  6
```

Now a particular physical movement does not always correspond to the same digit.

# 52. Important Comparisons

## Symmetric vs Asymmetric Cryptography

| Symmetric | Asymmetric |
|---|---|
| Same key for encryption/decryption | Public/private key pair |
| Fast | More computationally intensive |
| Good for large amounts of data | Good for key establishment/signatures |
| Key must be shared securely | Public key can be distributed openly |
| Example: AES | Examples: RSA, DH |

---

## Public Key vs Private Key

| Public Key | Private Key |
|---|---|
| Shared openly | Kept secret |
| Used by others to interact securely with owner | Used only by owner |
| In RSA example: $(n,e)$ | In lecture's simplified RSA representation: $d$ |

For encryption:

```text
Encrypt -> recipient's public key
Decrypt -> recipient's private key
```

For signatures:

```text
Sign   -> sender's private key
Verify -> sender's public key
```

---

## Hash vs MAC

| Hash | MAC |
|---|---|
| No key | Shared secret key |
| Anyone can compute | Key holders compute |
| Message fingerprint | Keyed message authentication |
| Cannot by itself prove sender identity | Shows sender knew the shared secret |

---

## MAC vs Digital Signature

| MAC | Digital Signature |
|---|---|
| Symmetric secret | Public/private key pair |
| Both parties know same key | Only signer knows private key |
| Verification limited to key holders | Public verification |
| No public non-repudiation | Supports non-repudiation |

---

## Encryption vs Authentication

```text
Encryption
-> "Can an attacker read this?"

Authentication / Integrity
-> "Was this changed?"
-> "Who created/sent this?"
```

They solve different problems.

# 56. Final Takeaway

> [!important]
> **Cryptographic security has two levels:**
>
> 1. **Algorithm-level security**
>    - mathematics
>    - key sizes
>    - hard computational problems
>
> 2. **Implementation-level security**
>    - timing
>    - power
>    - EM leakage
>    - physical behavior
>
> A mathematically secure algorithm such as AES can still be compromised if its implementation leaks information.

The transition into the next lectures is therefore:

```text
"How can we observe physical leakage
and use it to recover a secret key?"
```

That is the central problem of **Side-Channel Analysis**.
